The operator's solution is a work repository and is not sent anywhere by this session. The walk uses darndestdabbler/ContosoUniversity, one of the six public forks of the maintenance walk: an ASP.NET MVC 5 application on .NET Framework 4.8.1 with Entity Framework, a solution kept under src/, and enough of a data layer and a UI to have something to get wrong.

Two things are known from the source and are not what the walk is for. The suite gate already says a repository of documents "has nothing to run and is inapplicable, not passed". And every step must declare a check, prose steps included. What is not known is what the walk is for:

  • What the reviewer is given. It reads the diff against the session's section of the plan and the declared non-goals. Nothing in the verification code names source material, so a reviewer may be judging a page about data access against code it was never shown. Whether a reviewer reached through a seat reads the code for itself is not known.
  • Whether the loop ends. A reviewer of prose can raise findings about taste for seven rounds. Findings should be errors -- a requirement missed, the code contradicted, an earlier page contradicted, a stated rule broken -- and preferences should be Minor, which ends the loop.
  • What a suite can honestly be for documentation, and what a check can be on a locked-down Windows machine that may have neither Node on PATH nor a free hand with PowerShell.
  • What the diff looks like. A paragraph written as one long line shows a three-word edit as the whole paragraph replaced. One sentence per line may be what makes a prose diff reviewable.
  • Which sentences the framework prints assume code.
  • What a person's review costs and catches that the suite and the reviewer did not.

The plan written by hand has six documentation sessions, of which this walk runs two: a solution map with the commands that build and test it; a glossary of the domain's terms as the code uses them; how database access is done, traced through one entity; how a request reaches a page and comes back, with the UI tools named; what to touch to make each common kind of change; and a hand-over page a model reads first. The repository declares one suite in dabbler.yaml, a short script it holds itself: every relative link resolves, every path a page names in backticks exists in the code at the pinned commit, and the sibling checkout is at that commit. It does not claim that a type or a member a page names exists: a text search cannot promise that.
