# Set 115 Session 4 — verification conventions

Read this before the change set. It states the agreed baseline so a round
spends its findings on real defects rather than on the ground truth.

## What this session shipped

Two deliverables, both on the Work Explorer's in-flight session row.

### 1. The close-out obligations, computed in Python and read from a file

`close_preflight` already reported every unmet close-out obligation in one
pass with no side effects. It now also **serializes** that report:

- `--write` runs the report exactly as before — same stdout, same exit
  code — and additionally writes
  `<session-set-dir>/.dabbler/close-obligations.json`. The "wrote …"
  notice goes to **stderr** so `--json` stdout stays parseable.
- `--check` compares the serialized file against its inputs **without
  evaluating anything**: exit `0` fresh, `3` stale / absent / unreadable.
- The file embeds `PreflightReport.to_dict()` **verbatim** under `report`.
  One spelling, deliberately: this module has already shipped two
  surfaces of one report that disagreed (`would_close` said `true` while
  the human report said "NOT yet decided").
- `inputs` is a SHA-256 per **top-level file of the whole session-set
  directory**, not a curated filename list, because obligations derive
  from the disposition, the state file, the activity log, the spec, the
  change log, three ledgers and every `s<N>-*` verification artifact.
- `volatileInputs` carries one git fingerprint (`HEAD` + `git status
  --porcelain --branch`), and `Obligation.volatile` is a **derived**
  property, true exactly for `GIT_BACKED_CHECKS`.

The extension reads it: `readCloseObligations` (`utils/fileSystem.ts`)
re-digests the set directory and reports `fresh | stale | absent |
unreadable`; `workExplorerTreeModel.ts` renders a **Close-out** group row
under the in-flight session that expands to one row per obligation.

### 2. The `<- here` marker removal, finished in TypeScript

Set 120 S3 removed it from Python under an operator ruling and was
forbidden from touching the extension (its standing decision 3). This
session removed `HERE_MARKER` and its render site, `markHere`, its
`TERMINAL_STATUSES` table, and the `StepRow.isHere` field; stripped
`isHere` from the shared parity corpus; and replaced the two Python
guards that existed only to keep that field alive.

## Four journaled decisions this round should read as settled

All four are in `decisions.jsonl` (session 4) with options and
consequences. They are **decisions, not oversights** — please grade a
disagreement as a design dispute rather than as a defect.

- **The projection is an ignored per-machine cache, not a tracked
  record.** It is written mid-session, which is *after* a verification
  round is stamped, every time. A tracked file in the set directory
  would stale its own round and buy a metered backstop round at close —
  the failure Sets 111 S2, 112 S3 and 114 S1 each paid for. Putting it
  under the already-ignored `.dabbler/` makes that structural rather than
  one more filename in an exemption list. A fresh clone therefore reads
  `absent`, which is a designed state, not a gap.
- **Freshness is two questions.** Two of the fourteen obligations read
  git, and committing changes no byte any content digest covers. The CLI
  checks both halves; the tree checks the content half and labels the
  volatile rows "as of", because spawning git on a redraw path is the
  same defect as calling the 2-7 second preflight from the renderer.
- **The obligations are one grouped row, not fourteen flat ones.**
- **The marker removal is the whole derivation, not the two sites the
  spec names** (L-069-1 — the spec says so in the same step).

## Baseline — what is already true before this change set

- **Layer 1 (pytest).** The full suite is run at close, after the last
  code change, and recorded through `run_of_record`. Targeted runs during
  the session: `test_close_preflight.py -k Projection` 16/16 pass;
  `test_step_row_parity.py` 33/33 pass.
- **Layer 2 (tree-provider harness).** `npm run test:unit` — **1774
  passing, 1 pending**, zero failing, after these changes.
- **Layer 3 (Playwright).** Full `npm run test:playwright` is run after
  the last edit (L-064-12: the tree model is in scope). **42 scenarios**
  in 17 files — 41 before this session, plus the new close-out rendering
  scenario.
- **The extension version is deliberately NOT bumped.** The operator
  ruled on 2026-08-11 that the next Marketplace push happens once, after
  Sets 120 S3 and 115 land; `CHANGELOG.md`'s `[Unreleased]` section holds
  this work and `package.json` stays at the staged `0.51.0`. A missing
  version bump is the recorded plan, not an oversight.
- **`dist/extension.js` and its map are committed build output**,
  regenerated by every `npm run compile`. They are excluded from the
  work-diff digest by `verification_stamp.WORK_DIFF_BASE_EXCLUDES` and
  are not part of the change to review.
- **The set's own bookkeeping files** (`activity-log.json`,
  `decisions.jsonl`, `checklist-posts.jsonl`, `session-events.jsonl`,
  `session-state.json`) are written by sanctioned writers as the session
  runs. They are records *about* the work, not the work.

## Out of scope by design

- **No new gate.** The projection reports; only the existing gates
  refuse. A finding that this should block a close is a scope dispute.
- **No lifecycle model in the renderer.** The original Session 4 proposed
  deriving obligations from six ledgers; `close_preflight` already reads
  those predicates, so an obligation it does not cover is a bug **in the
  preflight**, not a reason for a parallel model in the tree.
- **The `[?]`-versus-`not-started` divergence for unknown STEP status
  tokens** (`step-ledger-findings.md` §4) is untouched. It predates this
  session, needs a fifth authored glyph asset, and the strict writer has
  already closed the population that produces it.
