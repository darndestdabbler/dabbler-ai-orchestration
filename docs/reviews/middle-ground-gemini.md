# Review of the Middle Ground Proposal

## 1. Verdict

Ship it with these changes. This shortcut succeeds because treating external dependencies as read-only, extracted APIs drastically reduces the context budget and sidesteps the need to author new contracts for existing code. To make it survive in the wild, you must enforce the black-box boundary mechanically by denying the AI access to the referenced source code entirely, rely on standard ecosystem tools rather than LLMs for API extraction, and immediately fix the defects in the control plane that leak credentials and forge approval records.

## 2. Where it breaks first

1. **Stale References causing hallucinated integrations.**
   *Scenario:* A referenced component's JSON manifest points to a repository but doesn't pin a commit. The external repo merges a breaking change. The local API summary isn't refreshed. The AI writes code against the old API, which passes local unit tests (if using mocked stand-ins) but fails spectacularly during the actual integration build.
2. **Cross-repo PRs failing on authentication.**
   *Scenario:* The AI proposes a change to a referenced component. Since `checks.py::_spawn` (rightfully) strips credentials to protect API keys, the AI's script tries to invoke `git push` or `gh pr create` and fails because it lacks the necessary GitHub/AzDO auth tokens in its environment. 
3. **API Extraction failing on uncompilable states.**
   *Scenario:* The referenced repository is mid-development and temporarily broken. If the API extraction relies on a compiler (`docfx` / `javadoc`), it crashes. The AI receives an empty API surface and deletes all integration code that depends on it.

## 3. One-way doors

1. **The Reference Manifest Format.** 
   If you invent a bespoke JSON schema for referenced repositories now, you create a migration nightmare when moving to the fuller architecture's `solution.yaml`.
   *Fix (1 day):* Use the exact `ProjectionComponent` schema already defined in `tools/dabbler-ai-orchestration/src/providers/solutionTreeModel.ts` and `solution.yaml`, simply adding a `kind: "referenced"` or `readonly: true` flag. 
2. **The VS Code Tree Model.**
   Baking the two-section split deeply into `workExplorerTreeModel.ts` will entangle the UI rendering with the orchestration logic, making it impossible to move away from VS Code later.
   *Fix (2 days):* Keep the projection logic entirely in Python (`ai_router.workflow`). The Python process should emit the two buckets, and `solutionTreeModel.ts` should only blindly render what it is handed. 
3. **Using AI to extract APIs.**
   If you use an LLM to summarize the referenced API, you lose mechanical determinism. The "contract" becomes probabilistic, meaning a second extraction might omit a critical method. 
   *Fix (3 days):* Mandate mechanical extraction tools (`docfx`, `javadoc`). If they fail, the reference fails to load.

## 4. The seven open questions

1. **How is the public API extracted, per language?**
   Mechanically, using existing ecosystem tools. For .NET, use `docfx` or `dotnet format` to dump public signatures. For Java, use `javadoc`. Do not use AI. Staleness is detected by comparing the local extraction's git hash against the remote repository's `HEAD`.
2. **What pins a referenced component?**
   A specific git commit SHA, stored in the reference JSON. When the external repository moves ahead, the API surface does *not* change until the human operator explicitly clicks "Update Reference," which fetches the new SHA and re-runs the mechanical extraction.
3. **Is the black-box rule mechanically enforced or prompt-enforced?**
   Mechanically enforced. The control plane clones the referenced repository into a directory *outside* the AI's workspace. It runs the extraction tool, and copies *only the resulting API markdown* into the AI's context. The AI literally cannot read the source files.
4. **Cross-repo pull requests must work on both Azure DevOps and GitHub.**
   The simplest workable solution is to use the host OS's existing CLI tools (`gh` for GitHub, `az repos` for Azure DevOps). The human operator authenticates these CLIs once on their machine. The Python control plane (which retains the environment variables, unlike the AI sandbox) executes the PR creation command based on a patch file generated by the AI.
5. **Documents have no compiler. What generates the summary?**
   A simple Python Markdown parser running in the control plane that extracts `H1` and `H2` headers and the first paragraph under each. It is refreshed exactly like code: manually updated by the operator, pinning a specific commit SHA of the document repo.
6. **Which parts of this are one-way doors?**
   The two-section tree is a clean subset of the fuller architecture *if* the backend treats both as standard components with a `readonly` boolean. The JSON reference manifest forecloses the future *unless* it structurally mirrors the future `solution.yaml`. 
7. **`activity-log.json` as a display source.**
   This is consistent. It is safe to use `activity-log.json` for display in the VS Code UI, provided that `ai_router/workflow.py::fold` continues to strictly ignore it and exclusively derives actual state transitions and gate evidence from the append-only `events.jsonl`. 

*(Self-correction/Shape constraint paragraph)*: The UI shape (Referenced vs Editable) is acceptable for v1, but collapsing the Referenced section by default is a mistake. Out of sight means out of mind, and developers will duplicate existing external logic in the Editable section simply because they didn't see the referenced API available to them. 

## 5. The smallest v1

*   **Security & Truth Fixes (2 days):** Strip credentials from AI execution in `checks.py::_spawn`, and fix invalid authority in `verdict.py::is_doc_only_issue` (remove self-exemption) and `workflow.py::fold` (enforce step order and reject `simulated` reviews).
*   **Mechanical API Extraction (3 days):** Wire up Python subprocess calls to `docfx` (or `dotnet tool`) and `javadoc` to extract public interfaces, saving them as markdown text.
*   **Isolated Reference Context (2 days):** Modify the control plane to clone referenced repos into a temporary AppData/tmp folder, extract the API, and inject only the API text into the AI's context.
*   **UI Tree Split (2 days):** Update `solutionTreeModel.ts` and `package.json` views to render the "Referenced" (read-only) and "Editable" buckets based on a flag in the Python projection.
*   **Cross-Repo PRs (3 days):** Implement a Python handler in the control plane that takes an AI-generated patch and uses `subprocess.run` to call `gh pr create` or `az repos pr create` using the host's native environment.

**Total Cost: 12 days.**

## 6. Prior `[must]` items re-ranked

*   **v1 (Cannot ship without it)**
    *   *Credential isolation:* `checks.py::_spawn` must not pass `DABBLER_*` or `*_API_KEY` to AI-authored code.
    *   *Immutable Truth:* `workflow.py::fold` must enforce legal step orders and reject `simulated` flags as valid gate evidence.
*   **Soon after (Lands within a few releases)**
    *   *Git Worktree isolation:* Modifying `checks.py` to use `git worktree add` instead of `snapshot_worktree_tree` for test execution, providing real filesystem rollback without full containers.
*   **Drop (Written for a different system)**
    *   *Moving off VS Code to a static browser UI:* The operator has mandated VS Code for the shortcut.
    *   *API Proxy Container:* Stripping environment variables achieves the exact same credential protection for local execution with zero moving parts.
    *   *Docker/Podman Sandbox:* The performance penalty on Windows NTFS is too high; local OS execution is accepted.
