ISSUES FOUND

- **Issue 1:** A4.1 misclassifies unchanged untracked files captured in the round-completion snapshot as post-round shipped-code changes.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/verify_session.py:1470`, `ai_router/verify_session.py:1888`, `ai_router/post_round_delta.py:227`, `ai_router/post_round_delta.py:281`, `ai_router/verification_stamp.py:928`, `docs/planning/session-set-authoring-guide.md:873`
  - **Failure scenario:** A typical implementation session adds a new shipped file, leaves it untracked until the final close-out commit, runs verification, then the full suite fails and the only post-suite fix is under a declared test surface. `record_round_completed` correctly anchors a tree snapshot containing that untracked shipped file, but `post_round_delta` later reuses `work_diff_binding_paths`, which unconditionally unions the current `git ls-files --others` output. The unchanged file is still untracked, so the classifier reports `shipped-code` instead of `test-only`, causing the A4.1 “owes nothing” path to fail for a common new-file session.
  - **Acceptance criterion:** `JUDGMENT - A post-round delta classifier case with an anchor tree containing an unchanged untracked shipped file plus a later test-only edit must classify as test-only, not shipped-code.`
  - **Details:** **Violation:** the guide says “A4.1 — a post-suite fix to one or more tests only (and not to code) does not trigger any re-verification,” and `post_round_delta` claims to classify “everything that changed since the session’s recorded verification round.” **Impact:** the central A4.1 reduction is not delivered for sessions that create new files before verification; users following the classifier get told to buy a remediation review even though only tests changed after the round. **Evidence:** `snapshot_worktree_tree` captures untracked files in the completion tree, `record_round_completed` stores that tree, `classify_delta` passes it to `work_diff_binding_paths`, and that helper adds every currently untracked path without comparing it to the anchor tree. The correct behavior needs a tree-to-current comparison that does not count unchanged paths already present in `worktreeTreeAtCompletion`.
