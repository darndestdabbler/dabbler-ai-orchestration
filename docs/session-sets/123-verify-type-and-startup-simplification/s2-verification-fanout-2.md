- **Issue 1:** The same-provider fallback is not actually reachable/usable for the target Direct API degraded case.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/__init__.py:1184`, `ai_router/__init__.py:1220`, `ai_router/config.py:129`, `ai_router/config.py:148`, `ai_router/config.py:154`, `ai_router/models.py:164`, `ai_router/router-config.yaml:448`, `ai_router/router-config.yaml:602`, `ai_router/providers.py:258`
  - **Failure scenario:** A typical Direct API session on an Anthropic/Claude orchestrator with only `DABBLER_ANTHROPIC_API_KEY` set is exactly the degraded case this session exists to permit. It still fails before producing any qualified verdict: `route()` calls `_init()` before `_direct_api_precondition()`, and `_init()` loads config with `require_api_keys=True`, whose validator requires every enabled provider key. If that early gate is relaxed, the degraded path only removes the orchestrator exclusion; the session-verification pin still selects `gpt-5-6-sol`/OpenAI, so dispatch then fails on missing `DABBLER_OPENAI_API_KEY` instead of using the available same-provider Anthropic key. This is probable because the shipped config enables multiple providers and pins session verification to OpenAI.
  - **Acceptance criterion:** `JUDGMENT - In a committed DIRECT_API project whose orchestrator effective provider is anthropic and whose only available provider key is DABBLER_ANTHROPIC_API_KEY, session-verification must warn, route to an Anthropic verifier, and write the same-provider qualification instead of raising a missing OpenAI/Gemini key error.`
  - **Details:** **Violation:** the spec says “When that cannot be met, the session proceeds and the record says so” and “Check the precondition and warn without blocking.” **Impact:** the core objective of same-provider qualified verification fails for the users it was meant to unblock, so the merge would falsely claim the fallback works. **Evidence:** `route()` invokes `_init()` at `ai_router/__init__.py:1184` before the new precondition at `ai_router/__init__.py:1220`; `_init()` uses `load_config(..., require_api_keys=True)`, and `validate_provider_api_keys()` raises for any enabled missing provider key at `ai_router/config.py:129-159`. The shipped verifier pin is OpenAI (`ai_router/router-config.yaml:448-453`, `:602`), and `pick_model()` honors the task-type override when no exclusion remains (`ai_router/models.py:164-171`), after which OpenAI dispatch raises on the missing key (`ai_router/providers.py:258-262`).
