Why. Two sentences a stopped person is shown are false, and both cost a session on 2026-11-10 and 11.

The first, from a consumer repository and then from this one's own walk: an engine reports a step blocked, a person clears what it was blocked on, and the stop's own way on -- dabbler session next -- stops again on the spot. The pull re-issues the instruction at the same seq, the blocked report is still on disk and is not spent (reportIsSpent asks only whether its seq is lower), and askForStep judges it blocked a second time. The run moves only when the engine answers the step again, which nothing printed says. A rejected-thrice stop already resumes by leaving the refused answer behind and asking afresh; the comment on that code describes this exact loop, and a blocked stop was never given the same treatment.

The second: every stop's rollback choice says "Everything the session did is lost". It is not. rollback keeps the work no commit holds as one commit on a local branch, dabbler/rolled-back/s<N>-<time>, and has since it was written. A person weighing a rollback, and an AI consulted about one, are told the opposite of what is true, so a rollback reads as more expensive than it is and the work is found again instead of brought back.

What.

Step 1 -- a blocked step is asked afresh. Resuming past a blocked stop leaves the blocked report behind, as resuming past rejected-thrice leaves the refused one: the step's instruction is issued afresh and the engine answers it. Both resumes do it -- the one a call to session next makes and the one a Mechanic's fix makes. The refusal count is left as it is, because a blocked report was never a refusal.

Step 2 -- the sentences. The blocked situation's carry-on line says what happens: the step is asked again and the engine answers it. rollbackChoice says what a rollback keeps and where -- the branch -- and what it does discard: the session's place in the run, its rounds and its test runs. Both briefs dabbler consult prints say the same in one line, so a consult or a Mechanic that recommends a rollback knows the work comes back with git checkout <branch> -- <paths> or a cherry-pick, and says so to the person. docs/driving-a-session.md says how a blocked stop resumes, beside where it says how a rejected-thrice one does.

Non-goals. Any change to how a step is reported blocked, to who may cancel or roll back, or to the push loop, which invokes its engine and so always gets a new report. Removing reports from disk. A copy of rolled-back work anywhere but the branch that already holds it. Bringing the work back automatically.
