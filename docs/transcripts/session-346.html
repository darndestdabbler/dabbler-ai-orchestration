Session 346 of 362: The router says how an engine is started, and answers with data

Scope: packages/router/src/engines.ts (the launch line), packages/router/src/cli/session.ts (session launch, --json on start, defect-report), packages/router/src/cli/workspace.ts, packages/router/src/contracts/router.ts, packages/router/src/inProcess.ts, packages/router/test/engines.test.ts, tools/dabbler-ai-orchestration/src/commands/sessionCommands.ts, tools/dabbler-ai-orchestration/src/commands/cancelLifecycleCommands.ts, tools/dabbler-ai-orchestration/src/commands/openRepository.ts, tools/dabbler-ai-orchestration/src/test/suite/commandFlows.test.ts

Why. Start Session is two things any interface can do: run dabbler session start, then open a terminal whose program is claude or copilot. But how that program is started is written in the extension: the program's name, where the model goes, how the opening sentence is passed (differently for each engine), the sentence itself for a session, a consult and a Mechanic, the environment variable, the terminal's title. A second interface that wrote those again would be a second implementation of a rule.

The extension also reads four results out of printed text by pattern: the ways on that a refused start offers, where a defect report was written and where reports go, and the workspace file dabbler workspace wrote.

Step 1 -- the launch line. dabbler session launch --for session, --for consult or --for mechanic, with the engine, the model and the session where they apply, prints as JSON what to start: the program, its arguments with the opening sentence in place, the working directory, the environment to add, and the title. It starts nothing. The building of it moves from sessionCommands.ts to engines.ts.

Step 2 -- a start's result as data. session start --json says whether the session is registered, and when it is refused, why, and which ways on it offers (commit the changes, undo them, merge origin) each as the command that takes it.

Step 3 -- the other three. session defect-report and workspace return the paths and the address they print, as fields. The rollback's dry run is JSON already and gains its place in the typed result.

Step 4 -- the extension reads them. It opens the engine from the launch line and drops its own copy, and drops the four patterns. Nothing a person sees changes.

Non-goals. Where a terminal opens or what it is: each interface's own. Starting the engine from the router. Any change to the opening sentences. A fourth engine.

Tests. In engines.test.ts: the launch line for each engine and each purpose carries the model and the sentence where that engine takes them. In commandFlows.test.ts: the tests of Start, Consult and Open a Mechanic assert the terminal the extension opens, as now, and pass unchanged in what they assert.

Releasable. Yes, as 3.36.0 in session 348.
