**ISSUES FOUND**

**Issue 1:** Packaging can still report `published` after `pack` dirties the repository, so the release record can point at a tree that is no longer the tree that was verified.
- **Category:** Correctness
- **Severity:** Major
- **Evidence paths:** `ai_router/packaging.py`, `ai_router/router-config.yaml`, `docs/schema-reference.md`
- **Failure scenario:** A repository adopts the documented packaging hook and uses a normal pack command or wrapper that writes the package artifact to `{output}` **and** emits intermediates under the repo. The shipped examples point operators at `dotnet pack -o {output}`, and build commands like that commonly leave side files outside the final package directory. On the current implementation, `package()` snapshots `tree_digest` before `pack`, never checks the worktree again, and still returns `published` as long as an artifact appears in `{output}` and `push` exits 0. That means the feed can receive artifacts from a tree that no longer matches the verified clean tree, and the later close can fail `working_tree_clean`. Because packaging is expressly built around repo-defined build commands, this is a probable main-path failure, not a contrived edge.

- **Acceptance expectation:** `exit 0`
- **Details:** **Violation:** the new packaging docs claim that writing packages under `.dabbler/runs/<set>/s<N>/package/` means “the tree that was just verified stays the tree that was verified.” **Impact:** a declared pack command can mutate the repo and still produce a successful publication, so the pushed artifact may no longer correspond to the verified tree and the session can become uncloseable afterward. That is a merge-blocking provenance failure for a release step. **Evidence:** `_execute()` in `ai_router/packaging.py` takes `tree_digest = snapshot_worktree_tree(root)` before `pack`, then runs `pack` and `push` and returns `OUTCOME_PUBLISHED` without re-running any clean-tree gate or diffing the post-pack tree. The only enforced pack invariant is that `packaging.pack.argv` contains `{output}`. The examples in `ai_router/router-config.yaml` and `docs/schema-reference.md` therefore overclaim what the implementation actually guarantees. The correct behavior is to fail closed when packaging changes the repo outside machine-state paths, instead of reporting `published`.
