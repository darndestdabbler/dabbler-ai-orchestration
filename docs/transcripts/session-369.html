Session 369 of 372: An engine outlives Visual Studio

Scope: tools/dabbler-visual-studio/ (a new project, the engine host: a small program shipped in the package; the pane's connection to it; the package's build), Dabbler.VisualStudio.Core/ and its tests (the messages between pane and host), ci-suites.json if the host brings a test project, docs/uat/uat-visual-studio-engine-pane.md

Runs only if session 368's page says go.

Why. A session runs for an hour without the person, and Visual Studio is closed, restarted for an update or crashes within that hour as a matter of course. An engine that is a child of Visual Studio dies with it, and the work in flight is lost. Visual Studio's own terminal keeps its console host apart from the IDE for the same reason.

Step 1 -- the host. A program outside Visual Studio's process tree that starts the engine through ConPTY and keeps it running with no pane attached. One host per engine. It owns a process and its bytes and decides nothing: it takes the launch line it is given.

Step 2 -- attaching. The pane talks to the host over a named pipe only the same Windows user can open: output, input, size, and the engine's exit. One pane types to an engine at a time.

Step 3 -- coming back. A pane that attaches to a running engine shows the engine's screen as it is now, a full-screen prompt included, and takes typing at once. The step finds the way that does this for both engines (replaying what was kept, having the engine redraw, or both) and the page says which.

Step 4 -- ending. The host ends when its engine does. Closing a pane detaches and ends nothing, and the pane says so the first time. Ending an engine is a named action on the pane. A host whose engine has printed nothing and had no pane for a stated time ends its engine and itself.

Step 5 -- Visual Studio reopened. On opening a solution the extension finds the engines still running for that folder and offers each one's pane again.

Step 6 -- the walk, added to the page: an engine mid-answer, Visual Studio closed and reopened; the same with Visual Studio killed from Task Manager; two Visual Studio windows on two solutions, one closed. Each time the live prompt is back and takes typing, or the page says go no further.

Non-goals. Surviving a sign-out or a restart of Windows. Start Session. Any decision in the host: what runs, and whether it may, is the router's.

Tests. The messages between pane and host, each kind once, in the file named after them. That a second pane cannot type to an engine that has one. The rest is the walk.

Releasable. No.

Messages
