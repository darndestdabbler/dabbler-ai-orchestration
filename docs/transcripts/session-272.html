Session Plan

Session 272 of 278: An API out of credits pauses for funds, and Continue resumes it

Scope: packages/router/src/transports/api.ts (the retry ladder), packages/router/src/transports/copilot.ts (the error classes), packages/router/src/drive.ts (the stop and its ways on); tests in api.test.ts, copilot.test.ts and drive.test.ts

Why. A developer using Dabbler on a real project, 2026-10-21: when an API runs out of credits the framework keeps trying and then fails, where it should pause so the developer can fund the account. Session 170 made the failure carry the provider's own words, so OpenAI's credit_balance_exhausted no longer reads as "HTTP 429 Too Many Requests", and that is all it changed: callModel retries every HttpStatusError up to retry.max_retries with backoff and then throws "API call failed after N attempts", and the seat transport files "quota" with the rate limits. An empty account is not a transient fault. Retrying it spends minutes, and the session ends in a failure a person has to read past to find a billing problem that one sentence could have named.

Step 1 -- out of funds is its own condition. The API transport recognises an exhausted balance from the provider's own error -- OpenAI's insufficient_quota and credit_balance_exhausted, Anthropic's "credit balance is too low" -- and never retries it. Google answers both a rate limit and a billing limit with 429 RESOURCE_EXHAUSTED; only the billing case is funds, and a rate limit keeps its retries. The seat transport separates the seat's exhausted AI credits from a rate limit the same way.

Step 2 -- the session pauses. A call refused for funds stops the run with a stop of its own kind, naming the vendor, the key's variable or the seat, and where that vendor's balance is topped up. Nothing done so far is lost, and the ways on are one: add funds, then ask for the next instruction, and the run resumes in the phase it stopped in, making the same call again. Cancel and rollback are not named.

Step 3 -- the words where a person reads them. dabbler status and the stop's line in the terminal say "waiting for funds: <vendor>", so the pause reads as a wait and not as a failure.

Non-goals. The Authoring AI's own billing: its CLI tells the person itself. Any balance check before a call, or any polling of a vendor's balance. Any change to how a real rate limit or a timeout is retried.

Tests. In api.test.ts, a funds refusal from each of the three vendors' shapes is not retried and is told apart from a rate limit. In copilot.test.ts, the seat's credit exhaustion is its own class. In drive.test.ts, a verification call refused for funds stops with the funds kind, and the next instruction after it resumes the phase.

Releasable. Yes -- with 273 to 277, as 3.23.0 in session 278.
