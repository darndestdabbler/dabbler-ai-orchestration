## CI minutes — the spec's premise was wrong, and the measurement says so

The spec expected a "measurably smaller" test matrix to translate into
measurably fewer CI minutes. **It does not, and the honest number is
roughly zero.** Measured by checking out `HEAD` into a throwaway worktree
and timing exactly the nine test modules this session deleted:

```
210 passed in 3.64s
```

Against a full suite of **957s (15m57s)**, the deleted tests were **0.4%**
of the wall clock while being **6.1%** of the test count. The deleted
machinery was cheap, fast, well-unit-tested code; the suite's minutes live
in the slow integration and subprocess-spawning tests, which this set does
not touch. The three-OS pytest matrix multiplies that ~3.6s by three, so
the saving is on the order of **ten seconds per CI run**.

Two smaller, real CI reductions do land:

- the consumer-bootstrap snapshot job renders one tier instead of two;
- `test_cold_start_acceptance` runs one parameterisation instead of two,
  and each boots a repo and drives the real `start_session` entry point.

**Recorded as a finding, not padded into a claim.** The case for this
removal is that the framework has one verification story instead of two —
not that CI got cheaper. Session 3's acceptance gate should assert the
*absence of live references*, which is executable and true, and should not
be asked to assert a minutes saving that the measurement does not support.

The router-side residual is: changelogs and MIGRATIONS (records, exempt),
comments that now *narrate the removal* (`gate_checks`,
`check_migrations`, `runtime_mode`, `spec_config`, `close_session`), the
fail-loud message and its tests (which must contain the string to work),
and the generated `test-fixtures/cold-start/full/` tree — regenerated by
Session 2 from the templates it edits, per the journaled decision.

Session 2 owns the remaining 142 live files (extension, templates, docs);
Session 3's grep gate is what proves the end state, and it must exempt the
narrating comments and the fail-loud message by construction — a gate
that cannot tell "mentions the tier" from "declares the tier" would either
fail on its own error message or force the removal to be undocumented.
