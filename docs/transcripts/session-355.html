Session 355 of 362: The Configuration window in Visual Studio

Scope: tools/dabbler-visual-studio/ (the tool window, its view model, the picker dialog)

Why. A session cannot start until an engine and its models are chosen, and a developer must be able to see why a value is what it is.

Step 1 -- the window. A dockable tool window, Dabbler Configuration, with the rows dabbler view configuration --follow prints: Authoring AI, Reviewing AI and API Keys, each value with the layer that decided it, and the catalog's age.

Step 2 -- picking. A row that can be set opens a dialog listing its choices as the router gave them, each with its detail, and one this machine cannot reach shown as such with the reason. Choosing one runs the command it names. A model that is typed is asked for in a box.

Step 3 -- Keep as Machine Default, with its confirmation.

Step 4 -- the answer. The router's sentence after a change, or its refusal, is shown on the window.

Non-goals. Update the Catalog and Store a Key: session 356. The repositories and modules tree.

Tests. In the library: a row's choices become the dialog's list with the unreachable ones marked; choosing one yields its command.

Releasable. No.

Work Plan

Give Visual Studio a dockable Dabbler Configuration tool window that shows the rows dabbler view configuration --follow prints, and lets a developer change them. The window follows the open solution's repository. Where no solution is open it follows this machine's defaults alone (no --repo-root). It shows Authoring AI, Reviewing AI and API Keys with their rows. Each row shows its label, and its description, which carries the value and the layer that decided it. The root's description and tooltip head the window, and the tooltip carries the model catalog's age. The window is drawn again whole each time the router prints. A row's context menu offers its actions, and activating a row runs its click. An action the router marks unavailable says why on the window and runs nothing. A setting action opens a picker dialog listing its pick's choices as the router gave them, each with its description and detail. A choice this machine cannot reach is marked with its reason. What the router withholds is listed disabled, with its reason. Choosing one runs the command that choice names. A pick with a typed member asks for the model id in a box and runs its argv with the id appended. Keep as Machine Default asks the router's confirmation and runs its command once accepted. After any change, the router's sentence, or its refusal, is shown in an information bar on the window. The library holds the parts that decide. The configuration document types live in Configuration.cs, and ConfiguredChoice reads through them. The window's view model is ConfigurationTree. ConfigurationAsk turns a pick into the dialog's list, gives a choice's or a typed id's arguments, and gives an action's arguments after its confirmation. Each part has its tests.

Picking

Add ConfigurationAsk.cs to Dabbler.VisualStudio.Core. Items(pick) returns the dialog's list: each choice in the router's order, with its label, description, detail and its unreachable reason (marked, still choosable), followed by each withheld entry with its reason, which cannot be chosen. A choosable item carries its argv without the leading dabbler. Typed(pick, id) returns the typed argv without dabbler, with the trimmed id appended, or null for a blank id. Test both in ConfigurationAskTests: the choices become the list with the unreachable ones marked, and choosing one yields its command. The setting actions' ids join ConfigurationTree's runnable list: setEngine, setAuthoringModel, setMechanicModel, setMechanic, setReviewerTransport, setPrimaryReviewerModel and setAuxiliaryReviewerModel. In the extension, add PickDialog.cs. It shows the pick's title and a list of its items, with description and detail. An unreachable choice is marked with its reason, and a withheld item is disabled and shows its reason. It returns the chosen item, or null where dismissed. For a pick with typed, it is a box with the router's prompt and placeholder instead. Add ConfigurationActions.cs to run an action in the window's repository root (or the router's folder where no repository is followed). An action with unavailable says it on the window and runs nothing. An action with a pick asks through PickDialog and runs the chosen command off the main thread through LifecycleActions.RunRouterAsync. Then the router's sentence after the change (its output, made one line), or its refusal, is shown in an information bar across the window's top, with a warning icon for a refusal. ConfigurationWindow gains Say(text, refused), and ConfigurationControl gains a context menu of the node's actions and runs its click on double-click or Enter.
