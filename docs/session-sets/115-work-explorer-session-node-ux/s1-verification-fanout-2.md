ISSUES FOUND

- **Issue 1:** The TypeScript absent-state path adds and duplicates synchronous `spec.md` reads despite the explicit “No new file read” constraint.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `tools/dabbler-ai-orchestration/src/utils/sessionState.ts:155`, `tools/dabbler-ai-orchestration/src/utils/sessionState.ts:214`, `tools/dabbler-ai-orchestration/src/utils/progress.ts:106`, `tools/dabbler-ai-orchestration/src/utils/fileSystem.ts:953`, `tools/dabbler-ai-orchestration/src/utils/fileSystem.ts:1060`
  - **Failure scenario:** A repo has a supported spec-only session set with no `session-state.json`. Every Work Explorer scan calls `readStatus(dir)`, which invokes `inferStateInMemory`, then later calls `inferStateInMemory(dir)` again for the same row; each inference reads `spec.md` once through `specTitleMap` and again through `readTotalSessionsFromSpec`. This is probable because spec-only sets are explicitly supported and tested, and it materially violates the tree-scan performance constraint the plan called out.
  - **Acceptance criterion:** JUDGMENT - The absent-state TypeScript path derives titles and `totalSessions` from one `spec.md` read per inferred state, and `readSessionSets` reuses that inferred state instead of invoking `inferStateInMemory` twice for the same missing file.
  - **Details:** **Violation:** the plan says “Thread the map it already computes into the loop… **No new file read — if the change adds one, it is the wrong change.**” **Impact:** the Work Explorer’s supported missing-state branch now performs repeated synchronous disk reads/parses per row, undermining the performance constraint and making the implementation choice merge-relevant. **Evidence:** `notStartedPayload` calls `specTitleMap(...)`, whose extractor reads `spec.md`, then calls `readTotalSessionsFromSpec(...)`, which reads the same file again; `readSessionSets` reaches that inference once through `readStatus` and again when building `rawSd`.
