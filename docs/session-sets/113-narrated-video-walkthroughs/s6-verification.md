- **Nit:** The claim that “every true positive” remains detected is false for injected servants. If a custom servant returns summarized/model-authored content while the sandbox changes between guard derivations, `truth != again` causes `SandboxNotQuiescent`, which `pull_route` catches and continues past without comparing the dishonest result to a stable truth. This is non-blocking because production reportedly uses the canonical servant, but it directly refutes the stated invariant. Location: `ai_router/pull_verifier.py`. Fix: fail closed for noncanonical servants or bind verification to a snapshot.

- **Nit:** `_raise_for_status_with_body` promises handling for “non-2xx” responses but returns for every status below 400. A 3xx response from a redirected or misconfigured provider endpoint proceeds to JSON parsing instead of raising `BindingHTTPError` with the body. Location: `ai_router/pull_verifier.py`. Fix: accept only `200 <= status_code < 300`.

- **Nit:** The assertion that preserving response bodies “cannot leak a key” is unsupported. Provider gateways and proxies can return arbitrary bodies or echo sensitive request fields; embedding up to 800 characters directly in exception text can expose them through logs or skipped-run diagnostics. Location: `ai_router/pull_verifier.py`. Fix: avoid the absolute safety claim and apply structured redaction before surfacing bodies.

- **Nit:** The pytest ledger guard does not guarantee that the suite “must never append” to the shipped ledger. Location: `ai_router/tests/conftest.py, ai_router/tests/test_metrics.py`. Fix: always establish a scratch default for each test, allowing individual tests to override it afterward.

Alias-driven runs therefore lose the actual requested alias, and the fields cannot expose request/serve differences. Location: `ai_router/pull_critique.py`.
