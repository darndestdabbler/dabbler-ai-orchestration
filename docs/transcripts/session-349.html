Session 349 of 362: A Visual Studio extension that installs and finds the router

Scope: tools/dabbler-visual-studio/ (new: the solution, the extension's project, a library with no Visual Studio in it, its test project), dabbler.yaml (a suite), .github/workflows/test.yml, docs/uat/uat-visual-studio.md (new)

Why. The first of the Visual Studio sessions makes the smallest thing that can be installed, and settles what the later ones stand on: that one package installs on the Visual Studio versions the developers have, that it finds Node and starts the router, and that Windows Terminal does what session 351 needs of it.

Nothing in this folder is published before session 362.

Step 1 -- the package. An in-process extension in C#, with a manifest that installs on Visual Studio 2022 (17.14) and 2026. In-process because the later sessions need what the newer out-of-process model does not document: a file opened at a line, a comparison of two commits, an information bar, and whether a build or a debugger is running. It carries the router's built bundle as a file. Everything that does not need Visual Studio, which is starting the router, reading its JSON and the rows as C# types, goes in a library of its own so that it can be tested without Visual Studio.

Step 2 -- Node. On first use the extension runs node --version. Where Node is missing or older than the router needs, it says so in one sentence that names the version to install and says to restart Visual Studio afterwards, since Visual Studio reads PATH when it starts. It does nothing else until that is put right.

Step 3 -- the router, and what was run. One class runs node on the bundle with a verb and returns what it printed, and one keeps a --follow verb running and hands on each document. Every command run is echoed to a "Dabbler Commands" pane of the Output window, as the VS Code extension does. One menu command, Dabbler: Version, shows dabbler version to prove the road.

Step 4 -- Windows Terminal. By hand, on this machine, and written into docs/uat/uat-visual-studio.md: that a tab can be added to a window named for Dabbler, opening the window when it is not there; whether a tab added to an open window gets the environment it was started with, and if not, the form of command that sets it; what happens with no Windows Terminal installed, where the engine opens in a plain console window.

Step 5 -- the suite. The library's tests are a suite in dabbler.yaml, run whole at every close as this repository's others are, and a job in the test workflow builds the solution and runs them on a Windows runner.

Non-goals. Any window. Tests that run inside Visual Studio: they need it installed and cannot run in CI. Carrying Node. Visual Studio before 17.14. Publishing.

Tests. In the library's test project: the Node check reads a version line and refuses one that is too old; the router class returns a verb's output and reports a failure with the router's own words.

Releasable. No. The folder is not published before session 362.
