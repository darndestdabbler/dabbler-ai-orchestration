Engine

In the Visual Studio library, add TerminalSize.cs. TerminalSize.ToSend(columns, rows, last) returns the size to send to the engine, or null where either is below one or it equals the last size sent. Tests in TerminalSizeTests.cs: a zero or negative size is never sent, an unchanged size is not sent again, and a new size is. In the extension, add PseudoConsole.cs. It creates a pseudo console (CreatePseudoConsole) with pipes and starts a program attached to it (CreateProcess with PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE), with a working folder and environment given. It reads the output on a background thread, writes input, resizes (ResizePseudoConsole), and closes the console and ends the process on Dispose. Open Engine Here now reads the open solution's repository configuration as EngineTab does. It asks dabbler session launch --for consult through EngineLaunch.Arguments with that engine and model, and runs the launch line through PseudoConsole. The environment is the launch's own env, plus PATH with the router's folder first, as the Windows Terminal tab is given. The program is resolved with WindowsTerminal.ProgramPath, and the arguments are quoted with Router.Quote. A launch line with typed text is written to the engine as its first input. Output goes to the page as UTF-8 and the page writes it to xterm. Keystrokes come back from xterm's onData. The fit addon's columns and rows come back on every resize, and only what TerminalSize.ToSend returns resizes the console. The first size is taken before the program starts. Closing the pane or Visual Studio ends the engine, and the pane says when the engine has exited. Open Engine Here while an engine runs shows its pane. A refusal the router prints is said in a message box, as EngineTab says it.

Keys

In the Visual Studio library, add TerminalKeys.cs. It decides, without WPF, from a key name and its Ctrl, Shift and Alt modifiers, whether the terminal keeps a key while it has focus. It keeps Esc, Shift+Tab, Tab, the four arrows, Enter with any modifiers, Backspace, Ctrl+C and Ctrl+V. It lets go of Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+F4, Alt+F4, Ctrl+Alt keys Visual Studio uses for windows (Ctrl+Alt+L and the like), F-keys other than those an engine reads, and Ctrl+Q. TerminalKeys.OnCopy(hasSelection) answers Copy where there is a selection and Interrupt where there is not. TerminalKeys.OnPaste(hasText) answers PasteText where the clipboard holds text, and PassToEngine where it does not, so an image is left for the engine to read as Windows Terminal leaves it. Tests in TerminalKeysTests.cs: each kept key is kept, Ctrl+Tab and Ctrl+F4 are let go, a selection makes Ctrl+C a copy, no selection makes it an interrupt, and a clipboard without text passes Ctrl+V to the engine. In the extension, EngineWindow keeps those keys from Visual Studio's command routing while the WebView has focus. A kept key goes to the WebView, and one let go goes to Visual Studio. engine.js copies a selection on Ctrl+C and sends ^C otherwise. On Ctrl+V it pastes clipboard text through xterm's paste, which brackets it where the engine asked for bracketed paste, and sends the key itself where the clipboard has no text.
