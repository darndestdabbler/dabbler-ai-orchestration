ISSUES FOUND

- **Issue 1:** `close_preflight` reports the would-route backstop path as blocking because it evaluates `verification_integrity` before accounting for the close backstop.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/close_preflight.py:430`, `ai_router/gate_checks.py:1533`, `ai_router/close_session.py:1866`, `ai_router/close_session.py:2005`, `ai_router/close_backstop.py:953`, `ai_router/docs/close-out.md:185`
  - **Failure scenario:** A typical completed API session has no stamped verification evidence yet. The preflight reports `verification_integrity` as an unmet blocking gate and exits `1`, even though default `close_session` runs the backstop before the gate chain; if that backstop returns `VERIFIED`, it writes the verification artifact/ledger/disposition patch and the later gate chain can pass. This is probable because the spec identifies the missing-settling-evidence backstop path as the central expensive case.
  - **Acceptance criterion:** `JUDGMENT - With all non-verification gates satisfied and close_backstop.decide_backstop(...).would_route true, close_preflight.evaluate must report verification_backstop as a cost warning, must not include verification_integrity in unmet_blocking, and must exit 0 unless another deterministic pre-route blocking obligation is unmet.`
  - **Details:** **Violation:** the delivered docs claim the preflight reports “closing now SPENDS a routed round” as a **cost warning** “not a refusal,” and that it “can never refuse something the close allows.” **Impact:** the central expensive-case deliverable gives a false blocking verdict and the rendered summary says `close_session would refuse`, changing the merge decision because the preflight does not predict the close path it claims to predict. **Evidence:** `close_preflight.evaluate` runs every `GATE_CHECKS` predicate before appending the backstop obligation; `check_verification_integrity` fails an API disposition with no `sN-verification*.md`; but `close_session.run` invokes `run_close_backstop` before `_run_gate_checks`, and a verified backstop writes the artifact/ledger/disposition patch before the gate chain runs. The correct behavior is to model the close’s backstop-before-gates ordering, not to gate on the pre-backstop filesystem state.
