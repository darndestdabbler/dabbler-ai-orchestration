Why. From the field (dabbler-platform, session 21, 2026-11-09). A repository declared an e2e suite with expensive: true and required_for_close: false, red by design until a later session fixes the 12 tests it names. The run of record ran it whole, it failed, and the framework issued fix-run-of-record; the author rightly reported the step blocked, because fixing the tests was a non-goal and loosening the suite would touch a gate. The session could not reach the land.

The two halves of the framework disagree. landFacts owes only the suites with expensive && suiteRequiredForClose(suite), and judgeFreshness fails only a required verdict, so the close is content with a red non-required suite. But phaseRunOfRecord walks every expensive suite and treats any exit 1 as a run-of-record failure, whatever required_for_close says. required_for_close was split from expensive so that "runs in the run of record" and "the close demands it green" could differ; the phase never read the second half.

Step 1 -- a red non-required suite is recorded and the walk goes on. In phaseRunOfRecord, when test-evidence run exits 1 for a suite with suiteRequiredForClose(suite) === false, the failed record already written by the verb stands as the run of record, the driver logs one event (run-of-record-red-not-required, with the suite, its command and the job log) and continues to the next suite. A required suite is unchanged: tests-failed and fix-run-of-record, as today. unchangedRedStop names only required suites, so a red non-required suite never becomes that stop either. Nothing about the release path changes: wholeRunsBeforeRelease still stops a release on any red expensive suite.

Step 2 -- the words. docs/driving-a-session.md says, where it describes the run of record, that a suite declared required_for_close: false is run and recorded but its failure does not stop the session, and that a release still demands it green. version.json goes to 3.29.1 (a patch: a phase now honours a declaration it already accepted), stamped with npm run stamp:version, and the changelog gets a 3.29.1 section saying what changed for a developer.

Non-goals. Any change to what the close gate owes or to judgeFreshness. Any change to wholeRunsBeforeRelease. A new declaration in dabbler.yaml. Skipping the suite rather than running it: the record must still say it was red.

Tests.
