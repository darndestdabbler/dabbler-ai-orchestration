ISSUES FOUND

- **Issue 1:** Version-1 run journals are still rejected rather than migrated
  - **Category:** Completeness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/journal.py`, `ai_router/schemas/run-event.schema.json`, `tests/test_journal.py`
  - **Failure scenario:** A repository created by the immediately preceding run-core version contains schema-version-1 events. After upgrading, any command that reads that durable journal fails with `JournalCorrupt`; the only offered choices are to discard the active journal or keep using the obsolete router. This is probable for existing users upgrading the component and materially prevents continuity through the session-set collapse.
  - **Acceptance criterion:** `JUDGMENT - A representative version-1 journal containing set-addressed run and organization events can be opened or deterministically migrated by the current router, preserving its event sequence and session identity without requiring the user to abandon the journal or run the obsolete router.`
  - **Details:** **Violation:** The unresolved requirement is that “Existing set-based run journals [must not] become unreadable instead of being migrated,” consistent with the session requirement to “Migrate this set's own state rather than abandoning it.” **Impact:** Existing durable run history cannot participate in the collapsed model, so upgrading breaks normal status, recovery, and subsequent run operations unless users abandon history. **Evidence:** `journal.SCHEMA_VERSION` is changed to 2, `validate_event()` unconditionally rejects every lower version, and the error explicitly directs users to “start a new journal” or retain the old router. The schema only accepts version 2, while the new test verifies refusal by name rather than any migration. The remediation therefore improves the error message but leaves the prior defect intact. **Fix:** Add a deterministic version-1 reader/migration path that maps set-addressed records into the repository-session model while preserving durable history and refusing only genuinely ambiguous inputs.

- **Issue 2:** Re-anchoring still permits omission of the first remediation commit
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/verify.py`, `tests/test_verify.py`, `ai_router/schemas/baseline-reanchor.schema.json`
  - **Failure scenario:** After a round records an unreachable dangling tree, the author makes two remediation commits and supplies the first one as the anchor. `_legal_anchors()` accepts that first post-round commit, so the next review diffs from after that commit and never sees its fixes. This is probable because remediation normally begins immediately after the round, making its first commit the first commit after `recorded_at`; it can cause a reviewer to clear incomplete or incorrect remediation.
  - **Acceptance criterion:** `JUDGMENT - Re-anchoring cannot use any commit containing post-round remediation unless the system has trustworthy evidence that its tree is exactly the tree reviewed in the prior round; in the ordinary two-remediation-commit history, neither remediation commit may become the baseline.`
  - **Details:** **Violation:** The implementation claims that “Every later commit contains remediation the next round is supposed to see,” but nevertheless permits “the first commit made after” the round. **Impact:** Accepting that commit removes its remediation from the next fix delta, reproducing the exact scope-hiding defect the change claims to close and undermining the verification boundary. **Evidence:** `_legal_anchors()` adds `history[at_or_before - 1]`, the first post-round commit, to the legal set based only on timestamp. The test fixture explicitly names that commit `first_fix.py`, then `test_the_first_commit_after_the_round_is_legal` requires it to be accepted. A timestamp cannot prove that this commit merely materialized the reviewed tree rather than containing remediation. **Fix:** Default to the last pre-round commit, or require an independently persisted, trustworthy tree binding before accepting a post-round commit as exactly the previously reviewed tree.
