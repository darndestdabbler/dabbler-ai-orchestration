Session 317 of 322: The reviewing vehicle's row warns only when something is wrong

Scope: tools/dabbler-ai-orchestration/src/providers/solutionTreeModel.ts, tools/dabbler-ai-orchestration/src/test/suite/solutionTreeModel.test.ts, version.json and the manifests npm run stamp:version writes, tools/dabbler-ai-orchestration/CHANGELOG.md

Why. The operator's report, 2026-11-11, on 3.32.1: the Vehicle row under Reviewing AI shows a warning mark that nothing clears. Choosing a vehicle on the row does not clear it, and neither does reloading the window.

The cause is in how the row is drawn. descriptorFor adds the mark to a Vehicle row whenever any layer below the deciding one names a value. For the reviewing vehicle one always does: the configuration the distribution ships names transport.profile, so every repository's row has at least one layer underneath, and the mark is on every reviewing Vehicle row on every machine. A repository that names its own vehicle, over a machine default that agrees with it, shows the mark for doing exactly what the product asks. The authoring Vehicle row has no shipped layer under it, which is why the same rule leaves it clean.

The mark was added when a persisted environment variable could override a person's choice with no surface able to show it. That variable is retired. What remains under a choice is the machine's default and the shipped default, and one layer overriding the next is how the layers are meant to work. It is not something for a person to fix.

The report also says the tooltip called the choice the machine's default after the repository had named one. That was not reproduced: read on the reporter's repository with dabbler.reviewerTransport set, the router answers that the checkout decided, and the pane draws its row from that reading. Step 2 settles it on the running extension.

What.

Step 1 -- the mark. A Vehicle row no longer carries a warning mark because a lower layer names a value. Its description is the vehicle and whose choice it is, and nothing else. The tooltip keeps every line it has: what decided, and each layer it overrides with that layer's value. The mark for the npm Copilot shim on the authoring row stays, because that one is a fault a person can fix.

Step 2 -- the row on a repository that names its vehicle. With dabbler.reviewerTransport in the checkout's settings, a machine default and the shipped default beneath it, the row reads api · this repository and its tooltip says the choice is this repository's. The existing test of the Vehicle row is extended to that case, drawn from the reading the router gives for such a repository. The operator sees the row itself on 3.32.2 when retaking the screenshot; a pane that still names the machine there is a defect of its own and a session of its own.

Step 3 -- the number. version.json goes to 3.32.2, stamped with npm run stamp:version -- a patch: one row drawn correctly. The changelog's 3.32.2 section says the reviewing Vehicle row no longer shows a warning for an ordinary choice.

Non-goals. A new mark for a different condition on this row: none is added until an incident asks for one. Any change to how the layers are read, or to dabbler configuration explain. The marks on the model rows, which report a selection the vehicle does not list or a reviewer from the author's own provider. Retaking the operator's screenshot, which is theirs to do on the released build.

Tests. No test is added. The Vehicle row's existing test in solutionTreeModel.test.ts changes with the behaviour: a row with layers beneath its choice carries no mark and still lists them in its tooltip.
