Why. A Copilot seat now lists three models Microsoft trained itself: mai-code-1.1-flash, mai-code-2-flash and mai-code-2. The catalog on the operator's machine has read all three, enabled, since 2026-11-18, and records each with no vendor, because the seat states none and the id-prefix table knows only claude, gpt, o1, o3, o4 and gemini. A model with no vendor is never offered as a reviewer, and Start refuses it as the author with words that say it is not in the catalog, which is untrue. Nobody can choose these models for anything.

They are a fourth vendor and not OpenAI under another name. Microsoft's model card of 2026-11-17 says both MAI Code 2 models were "pre-trained and post-trained by Microsoft from scratch", names Microsoft's own MAI-Base-2 as the only dependency, and says the Flash model was distilled from "a larger in-house MAI teacher model". That is Microsoft's own account and nobody outside can audit it; it is the same standing the other three vendors' accounts have.

What.

Step 1 -- the vendor. An id that begins mai names the vendor microsoft, and microsoft is a vendor a seat may front. After a free dabbler discovery refresh, the three models are recorded with that vendor, are offered for the author and for both reviewers on the seat, and answer to the cross-vendor rule as any other model does: a Microsoft model may review work an Anthropic, OpenAI or Google model wrote, and may not review work a Microsoft model wrote.

Step 2 -- a catalog read before this. A machine whose catalog was read by an older router still records the three with no vendor. A person who chooses one there is told that the catalog lists the model and names no vendor for it, and that dabbler discovery refresh reads it again for nothing. The same words are given for any listed model whose id names no vendor, where today's say it is not listed. Nothing is placed by guessing at the time a session starts.

Step 3 -- the words. The --provider help of session start and session next names four vendors. docs/schema-reference.md and docs/model-and-pricing-sources.md say that microsoft is reached through the seat only: there is no key for it, and no direct endpoint. The guide names the fourth vendor wherever it names the three.

Step 4 -- the number. version.json goes to 3.38.0 (a minor: a vendor a person could not choose before), stamped, and the changelog says what a person with a Copilot seat can now choose.

Non-goals. A direct-API transport for Microsoft Foundry, where MAI Code 2 Flash is also served. A key or a credential row for Microsoft. Any default that picks a Microsoft model for a role nobody chose it for. A ranking of the three: which one reviews is the person's choice in Configuration. A vendor field read from the seat, which states none. Anything in the Visual Studio extension, which prints what the router says.

Tests. In copilot.test.ts: an id beginning mai is placed as microsoft, and a seat entry for one is recorded with that vendor. In identity.test.ts: a seat session whose model is a mai id resolves to microsoft; a listed model with no vendor is refused with words that name the refresh. In roleSelection.test.ts: a Microsoft model is offered to review an OpenAI author and removed for a Microsoft one. The docs check reads the changed pages.

After it lands, by the operator. One session whose reviewer is mai-code-2, chosen in Configuration, is the only proof that it reviews well enough to keep. mai-code-1.1-flash is reported, by one source and not by GitHub, to leave Copilot on 2026-12-18: choose one of the other two.
