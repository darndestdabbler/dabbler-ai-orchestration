# Session 4 — remediation, rounds 1 and 2

Three blocking findings across the two discovery passes. All three accepted and
fixed; none disputed.

---

## R1-F1 (Major, Completeness) — the measurement was not the four-session measurement

**Accepted.** The report shipped covering sessions 1–3 with a line saying
session 4 would be appended later, and the saved JSON was the output of the
prototype script (snake_case keys), not of the shipped module. Both are real:
the spec's Step 4 says *"now across all four sessions"*, and a raw artifact that
does not match its own tool's output shape is not reproducible evidence.

**Fix.**

1. `s4-doc-only-cap-measurement.json` is now regenerated by
   `python -m ai_router.measure_doc_only_cap <set-dir> --json <out>`, so its
   shape is the module's current shape by construction
   (`roundsPerSession`, `medianRounds`, `preCapMedianRounds`, camelCase
   `counterfactual`).
2. `s4-doc-only-cap.md` now covers **all four sessions**, including session 4's
   own rounds.
3. Added `--markdown` to the module and regenerated the report's table and every
   headline count from the JSON rather than typing them. A hand-maintained table
   drifts from its own data on the next round, which is the consistency-echo
   failure this repo keeps paying for (G-012).
4. The report opens with an explicit statement of the one thing that cannot be
   fixed: **a session cannot measure the round that reviews it.** The artifact
   is regenerated as the last act before close and states the traffic recorded
   at that moment; the shipped, re-runnable module is the durable answer, which
   is why it is a module and not a paragraph.

**What changed in the numbers.** Session 4's own three findings are all mixed
citations and none is doc-only, which strengthens the finding rather than
softening it: 13 of 23 (57%) mixed, up from 10 of 20 (50%).

## R1-F2 (Major, Correctness) — the round counter counted authorization rows as rounds

**Accepted, and it was a real false number in the headline deliverable.**
`sN-rounds.jsonl` carries two event types: `round-completed` (a metered round
that ran) and `operator-authorization` (permission to exceed a bound, which
costs nothing and runs nothing). `_round_counts` summed every non-blank line, so
session 1 reported **7** rounds when it ran **6**.

**Fix.** `_round_counts` now parses each line and counts only
`event == "round-completed"`, with the constant named and the reason documented
at `ROUND_COMPLETED_EVENT`. Malformed lines are skipped rather than counted.

**Falsifiers** (`TestRoundCounts`), one per direction, because a counter that
returns 0 would satisfy the first test alone:

- `test_an_authorization_row_is_not_a_round` plants the authorization row and
  asserts it is excluded.
- `test_the_look_alike_two_real_rounds_both_count` plants two genuine rounds and
  asserts both are counted.
- `test_a_malformed_line_is_skipped_rather_than_counted` plants unparseable
  text.

**Effect on the conclusion: none, and the report now says so more accurately.**
Corrected rounds are 6/5/4 rather than 7/5/4. Netting out the phased
`supplementary` round — a deliberate harvest, not a re-round opened by a finding
— gives 5/4/3, a median of exactly **4.0**, the pre-cap figure. The report's
claim was already that the cap moved rounds neither way because it never applied
to anything; the corrected numbers support that more cleanly than the inflated
ones did.

### Acceptance-criterion note: R1-F2's expectation collides with R1-F1's fix

The verifier's criterion for this finding is:

```
python ai_router/measure_doc_only_cap.py docs/session-sets/121-guidance-becomes-executable
expects exit 0, output contains "rounds per session: {1: 6, 2: 5, 3: 4}"
```

That command now exits 0 and prints:

```
rounds per session: {1: 6, 2: 5, 3: 4, 4: 2}  median=4.5  pre-cap median=4.0
```

**The substantive assertion is satisfied — session 1 reports 6, not 7** — but
the literal substring match fails on the trailing `, 4: 2}`, because the same
round's *other* finding (R1-F1) required session 4's own traffic to be included
and the criterion was authored before it was. The two criteria cannot both be
met as literally written; the fix satisfies the intent of both. The harness
reports this as `still-failing`, which is the harness working correctly — it
compares strings and cannot know the two findings interact. Recorded here rather
than worked around: **no output was shaped to satisfy a matcher.**

## R2-F1 (Major, Correctness) — the new cap test made the advertised headroom unusable

**Accepted, and this is the sharpest of the three.** The shipped gate treats a
corpus equal to the cap as legal (`over_cap = lines > cap`), and both
`router-config.yaml` and `guidance-candidates.md` state that the next earned
instruction line is admissible into the free slot this session created. The new
test asserted `len(live) < cap` as a permanent invariant, so promoting C-001 —
or any other earned line — would have reddened CI while the product gate stayed
green. A test that contradicts the behaviour it guards is worse than no test.

**Fix.** `test_the_cap_is_not_tautological_against_its_own_corpus` is replaced
by `test_the_cap_is_evidence_derived_not_a_restatement_of_the_corpus`, which
guards the property that actually matters and drops the one that does not:

- `len(live) <= cap` — the **shipped** semantics, so filling the free slot is
  legal here exactly as it is in the gate.
- `cap == gl.DEFAULT_INSTRUCTION_LINE_CAP` — the cap must remain the measured
  historical peak. This is the anti-tautology guard: a future session that
  re-derives the cap from its own corpus size (which is what forced S3 to 25)
  has to move the documented constant and state its basis, rather than quietly
  making the gate a restatement of the thing it gates.

The docstring records why the first formulation was wrong, so the next author
does not re-introduce it.

## Not changed, and why

**The counterfactual stays a measurement.** Two of the three findings concern
the accuracy of the cap measurement, and all three of session 4's findings are
themselves mixed citations — the class a widened cap would suppress. R1-F2, the
finding that corrected a false number in this session's headline deliverable, is
a mixed citation. That is now stated in the report as the argument *against*
widening. Acting on it either way remains an operator ruling: widening the cap
is a verification reduction, reserved by spec decision 5 and by the
constitution's hard carve-out.
