ISSUES FOUND

- **Issue 1:** Clean supplementary discovery passes do not consume the enforced discovery bound.
  - **Category:** Correctness
  - **Severity:** Major
  - **Failure scenario:** A normal session runs `--phase discovery`, gets Critical/Major findings, then runs the required supplementary pass and it finds nothing new. That is still the second discovery-family pass, but because no `sN-issues*.json` is written, a third supplementary/discovery pass is accepted without `--operator-authorized-round`. This is probable: “clean supplementary after blocking discovery” is a normal path, and the whole change exists because advisory-only bounds were already exceeded in practice.
  - **Details:** **Violation:** the task requires “refuse to run a third discovery pass … unless an explicit operator-authorization flag is passed” and “at most 2 discovery-family passes (`discovery` + `supplementary` share one budget).” **Impact:** the core release objective, “a third cycle is structurally impossible without recorded operator authorization,” is false for a common path, so the merge would still allow the verification-grinding behavior Set 111 S1 is meant to stop. **Evidence:** `count_phase_family_rounds()` counts only prior `sN-issues*.json` envelopes, while a clean supplementary pass writes no envelope and returns blocking via `supplementary_blockers_stand`; I reproduced `discovery` with findings → clean `supplementary` → third `supplementary`, and the third routed (`third_calls: 1`) instead of refusing. The bound needs a phase-pass record independent of findings envelopes, or otherwise must count clean supplementary attempts as completed discovery-family passes.
