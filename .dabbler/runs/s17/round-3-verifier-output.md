- **Issue 1:** Per-suite routing now preserves ownership, but constructs invalid targeted commands for the Java/.NET runners the session explicitly supports.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/affected.py, ai_router/testphase.py, tests/test_testphase.py`
  - **Failure scenario:** A mixed Java/.NET repository declares the plan’s documented commands, `mvn -q test` and `dotnet test`, and a shared change selects `src/test/java/AdderTest.java` and `test/AdderTests.cs`. The new code correctly separates ownership, but produces commands equivalent to `mvn -q test src/test/java/AdderTest.java` and `dotnet test test/AdderTests.cs`. Maven treats the appended source path as a lifecycle argument, while `dotnet test` expects a project, solution, directory, or built assembly rather than a C# source file. This is probable because Java/.NET repositories are the session’s explicit motivating use case and these are their ordinary suite commands.
  - **Acceptance criterion:** JUDGMENT - With Maven and .NET suites declaring `mvn -q test` and `dotnet test`, selecting one test from each must execute two valid runner-specific commands, each restricted to its owning test or safely running that suite’s full declared command.
  - **Details:** **Violation:** The plan explicitly says an external Java repository must be able to “declare `mvn -q test`” and requires “Affected tests as preverify,” but `affected.py` and `testphase.py` pass those opaque commands through the generic `targeted_command` path. The updated test proves the targeting contract is simple path appending by expecting `runner.py <test-path>`; neither the suite configuration nor these calls provide a Maven or .NET selector/template. **Impact:** The primary multi-ecosystem scenario reaches both owning suites but both invocations can fail before running any test, so the remediation does not deliver usable affected-test execution and should block merge. **Evidence:** `affected.py` generates each suite’s command with `targeted_command(s.command, result.for_suite(...))`; `testphase.py` does the same for each owned group; `tests/test_testphase.py` asserts raw path appending using only a synthetic runner that accepts that convention. The prior ownership defect is resolved narrowly—suite identities are retained and separate runs are created—but valid invocation of the cited real runners remains unsubstantiated and incorrect.
