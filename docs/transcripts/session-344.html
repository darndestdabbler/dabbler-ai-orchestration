Session 344 of 362: The router prints the Work Explorer's rows

Scope: packages/router/src/views/workExplorer.ts (new, moved: the model, the rule for which actions a row offers, the labels and icons, the verdict words), packages/router/src/cli/view.ts (new), packages/router/src/cli/dabbler.ts, packages/router/src/index.ts, packages/router/schemas/ (the rows' schema), packages/router/test/workExplorer.test.ts (new, moved), tools/dabbler-ai-orchestration/src/providers/ (the five model files go; WorkExplorerTreeProvider.ts stays), tools/dabbler-ai-orchestration/src/utils/fileSystem.ts, tools/dabbler-ai-orchestration/src/test/suite/

Why. The Work Explorer's model takes the router's reading of the sessions and returns plain rows: a label, a description, a tooltip, an icon, whether the row opens, and the actions it offers. It is 1,720 lines in five files, none of which uses VS Code, and it holds rules: Start Session is offered on the next session when nothing is in flight; Check this stop when a stop stands. A second interface must not work those out again.

Step 1 -- the move. workExplorerTreeModel.ts, ActionRegistry.ts, sessionsModel.ts, rowMenuHelpers.ts and verdictTokens.ts move to packages/router/src/views/workExplorer.ts, with the part of fileSystem.ts that gathers what the model is given: the reading, the activity of the run in flight, a Mechanic's memo.

Step 2 -- the verb. dabbler view work-explorer --repo-root <path>, which may be given more than once, prints the whole tree as JSON: each repository, its buckets, its sessions, and under a session its tasks, verification, findings and what needs attention. A row carries its id, its text, its icon by name, whether it starts open, the command a click runs, and its actions.

Step 3 -- an action is the verb a person would type. Each action on a row carries its id, its title, and the dabbler command it stands for with its arguments filled in, and says what it needs from a person first: a confirmation with its words, a reason, or nothing. Whether Cancel is forced is in the command, not left to the interface. An action that opens a file names the file and the line.

Step 4 -- the schema. The rows' shape is a schema under packages/router/schemas/, and the TypeScript type is generated from it as the progress reading's is. Session 350's C# types are written from the same file.

Step 5 -- the extension reads it. WorkExplorerTreeProvider.ts turns the router's rows into tree items as it does today, in-process. Which menu item shows on which row still comes from the row's actions. Nothing a person sees changes.

Non-goals. Any change to a row, a bucket, an icon or when an action is offered. Which folders are repositories: the interface says, since only it knows what is open. Refreshing: session 347. The Solution Explorer.

Tests. The model's tests, the action rule's and the labels' move to workExplorer.test.ts and are rewritten for node --test; none is dropped. One new test: the JSON the verb prints for a fixture repository validates against the schema and offers the actions the model's own tests expect. workExplorerTreeProvider.test.ts stays.

Releasable. Yes, as 3.36.0 in session 348.
