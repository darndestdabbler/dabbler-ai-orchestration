Scope: packages/router/src/bootstrap/detect.ts (the detectors, the project style, the test globs), packages/router/src/bootstrap/index.ts (what bootstrap writes and says), packages/router/src/bootstrap/templates.ts (PLAN_PROMPT, DECOMPOSITION_PROMPT, SHARED_BODY), packages/router/src/config.ts and packages/router/schemas/dabbler.schema.json (the posture member), packages/router/src/drive.ts (writeRootFiles), packages/router/src/ecosystem.ts (ensureRootFiles), packages/router/src/projectGraph.ts (a solution file below the root), packages/router/src/affected.ts (the plural test name), the tests named after each, docs/driving-a-session.md, README.md and tools/dabbler-ai-orchestration/README.md

Why. Staff are starting to use the framework to MAINTAIN repositories that already hold code: ASP.NET MVC on .NET Framework 4.5 and later, ASP.NET Core MVC, plain Maven web applications, Spring Framework WARs and Spring Boot services, each opened in Visual Studio, IntelliJ or Eclipse as often as in VS Code, by people who may never use this framework at all. The framework was built greenfield-first, and read against those repositories on 2026-11-10 it would do harm before it did work. Detection reads the repository root and nothing below it, so the common src/Thing.sln layout declares no suite, and a .csproj with no Sdk attribute -- the whole of .NET Framework -- is declared dotnet test, which cannot build it. The root-file scaffold runs before every step's checks and writes a .slnx beside that src/Thing.sln, with a Directory.Build.props that enables Nullable and ImplicitUsings; MSBuild imports that file into non-SDK projects too, and a C# 7.3 project stops compiling. The Maven test glob is *Test.java, so a Spring Boot repository's FooServiceTests.java is never the test named after FooService.java. And the planning prompt asks how production is split across tiers and what the module cuts are, then asks for "alignment" sessions first -- an invitation to restructure a WAR whose layout the maven-war-plugin depends on. Two advisors from two vendors read the same facts and reached the same shape, recorded in this session's consult: recognise the repository, confirm the posture with the person, and stand still in it.

What. A repository that holds code is read as one, and under the posture that follows the framework writes nothing it was not asked for.

Step 1 -- detection reads what is there. detect.ts reads two levels below the root, skipping bin, obj, target, node_modules and .git, so a solution file or a POM under src/ is found, and the suite it declares names that file (dotnet test src/Thing.sln, mvn -q -f src/pom.xml test), because a suite declares a command and no working directory. A .csproj whose root element carries no Sdk attribute is a different ecosystem, dotnet-framework: this session declares it with no suite command and a note naming session 307, which gives it one, rather than a dotnet test line that fails the first time it runs. .gradle.kts counts as Gradle. The test globs accept the singular and the plural for both languages (*Test.cs/*Tests.cs, *Test.java/*Tests.java), and the name of the test after a source file tries both.
