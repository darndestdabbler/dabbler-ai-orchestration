Session 347 of 362: The views follow the records

Scope: packages/router/src/views/follow.ts (new), packages/router/src/cli/view.ts (--follow), packages/router/src/cli/status.ts (--stalled-after-seconds), packages/router/test/follow.test.ts (new), tools/dabbler-ai-orchestration/src/extension.ts, tools/dabbler-ai-orchestration/src/utils/projection.ts, tools/dabbler-ai-orchestration/src/providers/SolutionTreeProvider.ts, version.json and the manifests npm run stamp:version writes, tools/dabbler-ai-orchestration/CHANGELOG.md

Why. A view is only right until a record changes. The VS Code extension knows which files to watch: the ledger, the plan, a run's records, the catalog and the preferences. That list is in extension.ts, in SolutionTreeProvider.ts and again in the key of the reading's cache. It is a rule about the router's own files, kept outside the router, in three places. A second interface would make it four.

Step 1 -- one list. packages/router/src/views/follow.ts says which paths each view depends on, for a repository. The extension's watchers and its cache key are built from it, and their own lists go.

**Step 2 -- --follow.** dabbler view work-explorer --follow and dabbler view configuration --follow print the view, then print it again whenever a path it depends on changes, one JSON document to a line, until interrupted. Changes close together make one printing. A document is whole each time: an interface replaces what it shows and compares nothing.

Step 3 -- the stalled threshold. dabbler status and the views take --stalled-after-seconds, which only the in-process call could pass.

Step 4 -- the number. version.json goes to 3.36.0 (a minor: new verbs), stamped with npm run stamp:version, and the changelog's 3.36.0 section says what sessions 343 to 347 give a person: dabbler terminal and dabbler view at a bare terminal, and nothing changed in VS Code.

Non-goals. Sending only what changed. A server, a port or a socket: an interface starts the verb and reads its output. Any change to how often VS Code refreshes.

Tests. In follow.test.ts: a change to the ledger prints the Work Explorer again and a change to a preference file does not; two changes close together print once. npm run check:version checks the stamp.

Releasable. Yes, as 3.36.0 in session 348.

Follow
