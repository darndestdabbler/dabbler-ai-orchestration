ISSUES FOUND

- **Issue 1:** The retention report ignores live guidance IDs that are missing from the ledger, so the cap and disuse report can silently undercount the corpus.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/guidance_ledger.py:679`, `ai_router/guidance_ledger.py:811`, `docs/session-sets/121-guidance-becomes-executable/spec.md:321`
  - **Failure scenario:** A future session adds/registers live guidance IDs imperfectly — especially Session 3’s planned project-guidance ID admission — and one live instruction marker is missing from `guidance-usage.json`. That is probable because registration is a separate state write, and the current report has no reverse check. The operator then runs `guidance_ledger report`; the unregistered instruction is neither counted against `instruction_line_cap` nor surfaced as never-used/missing, so the anti-rebloat mechanism can pass while the live corpus has already exceeded its evidence-backed cap.
  - **Acceptance criterion:** JUDGMENT - With a live guidance corpus containing an ID absent from `guidance-usage.json`, `guidance_ledger report` must count that ID against `instruction_line_cap` and surface a missing-ledger/never-used problem instead of silently treating the corpus as smaller.
  - **Details:** **Violation:** the spec requires “one compact record per guidance item” and ends with guidance prunable “deliberately on evidence of disuse.” **Impact:** missing ledger records become invisible to the only retention/cap report, which materially impairs the session’s core objective. **Evidence:** `retention_report()` iterates only `ledger.entries`, and `instruction_count()` also counts only ledger entries filtered by `governed_ids`; `corpus_ids()` is never used to add or fail missing live IDs.

- **Issue 2:** The canonical workflow’s Step 9 archival guidance still instructs operators to use the retired `last-used-set` / `guidance.disuse_window_sets` rule.
  - **Category:** Completeness
  - **Severity:** Major
  - **Evidence paths:** `docs/ai-led-session-workflow.md:2448`, `ai_router/guidance_meta.py:238`, `ai_router/guidance_ledger.py:967`
  - **Failure scenario:** On the final session of any future set, the orchestrator opens the workflow Step 9 procedure and follows the still-present “no `last-used-set` activity for default 20 sets” rule. That path is likely because Step 9 is mandatory and this document remains the procedure reference. Since `last-used-set` is no longer written, the operator is directed to stale evidence instead of the ledger’s active-session retention report.
  - **Acceptance criterion:** JUDGMENT - The Step 9 archival/reorganization procedure in `docs/ai-led-session-workflow.md` no longer tells operators to use `last-used-set` or `guidance.disuse_window_sets`, and instead points to `guidance_ledger report`, active-session retention, and batched operator-initiated pruning.
  - **Details:** **Violation:** Session 2 requires retention by active sessions and moving usage out of preload; the implementation retires `update_last_used()` and derives `instruction_window_sessions = 30`. **Impact:** the repo would ship contradictory operational instructions on the exact pruning decision this session is meant to make evidence-based. **Evidence:** the workflow still says archival is based on “no `last-used-set` activity” and “default 20 sets,” while the code now raises on `update_last_used()` and uses the ledger’s active-session settings.
