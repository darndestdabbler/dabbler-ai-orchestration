ISSUES FOUND

- **Issue 1:** The repository still ships a set-based run-core CLI/projection alongside the new repository-wide session model.
  - **Category:** Completeness
  - **Severity:** Major
  - **Evidence paths:** `docs/sessions/session-plan.md`, `ai_router/runcli.py`, `ai_router/runproject.py`, `tests/conftest.py`, `tests/test_runcore_fast.py`
  - **Failure scenario:** After migrating a repository to `docs/sessions/`, an operator uses the shipped run-core surfaces (`python -m ai_router.runcli ...` or the Explorer projection it writes). Those paths still require a set slug, discover work from `docs/session-sets/<slug>/spec.md`, and write `session-state.json` / `activity-log.json` / `change-log.md` back under `docs/session-sets/`, so the collapsed repository layout cannot be used through that CLI/projection at all. This is likely, not hypothetical, because the code remains live and its tests still seed and assert the old layout.
  - **Acceptance criterion:** `JUDGMENT - ai_router.runcli and ai_router.runproject no longer require a set slug and no longer read or write docs/session-sets/*/{spec.md,session-state.json,activity-log.json,change-log.md}; they must operate on docs/sessions/session-plan.md and the repository-wide sessions artifacts instead.`
  - **Details:** **Violation:** Session 14 says, “Remove the set level from the CLI, the state files, and the extension tree.” **Impact:** a public CLI/projection surface was left on the retired layout, so the collapse is incomplete and a migrated repo still has a second, contradictory way to register and project sessions. **Evidence:** `ai_router/runproject.py` still defines `SESSION_SETS_DIRNAME = "docs/session-sets"` and `write_documents()` still emits per-set `session-state.json` / `activity-log.json` / `change-log.md`; `ai_router/runcli.py` still resolves sessions by `set_slug` and adds `--set` arguments; `tests/conftest.py` and `tests/test_runcore_fast.py` still build and assert that old structure. The correct answer is to collapse or retire these shipped surfaces too, not leave them set-based.

- **Issue 2:** Cancelled sessions are not actually skippable, and the next registration rewrites them back to `not-started`.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `AGENTS.md`, `ai_router/session.py`, `ai_router/writers.py`, `ai_router/progress.py`, `tests/test_session.py`
  - **Failure scenario:** A user uses the new `session cancel` flow to skip abandoned work, then starts the next session. `session.start` computes the next session from completed sessions only, so it still expects the cancelled session number; if the user re-registers later work anyway, `register_session_start()` rebuilds every non-complete, non-current session as `not-started`, erasing the cancelled state and its metadata. That is a likely main-path use of the new feature, because per-session cancel/restore was added precisely to cancel one session while leaving the surrounding work intact.
  - **Acceptance criterion:** `JUDGMENT - With sessions 1=complete, 2=cancelled, 3=not-started in docs/sessions/sessions.json, python -m ai_router.session start must select session 3, and the resulting write must leave session 2 cancelled with its cancellation metadata intact.`
  - **Details:** **Violation:** `AGENTS.md` says that when no session is in flight, “the next is the lowest-numbered `not-started` one; `complete` and `cancelled` are skipped,” and `ai_router/progress.py` documents cancelled sessions as closed. **Impact:** the new cancel/restore surface cannot serve its intended purpose; cancelling a session either blocks all later sessions or gets silently undone on the next start, which would change a reasonable reviewer’s merge decision. **Evidence:** `ai_router/session.py` derives `requested`/`expected` from `completed = _completed_numbers(...)` and `max(completed)+1`; `ai_router/writers.py::_completed_numbers()` counts only `STATUS_COMPLETE`; and `_build_sessions_array()` rewrites every other session to `STATUS_NOT_STARTED`, dropping any cancelled state. `tests/test_session.py` exposes cancel/restore as the public CLI contract but does not cover starting past a cancelled session. The correct answer is to treat `cancelled` as a closed session in sequencing and to preserve cancelled records when rebuilding state.
