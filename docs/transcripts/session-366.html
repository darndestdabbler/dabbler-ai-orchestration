Session 366 of 367: A Word document is written as a document, and its text is reviewed

Scope: packages/router/src/drive.ts (the planning instruction), packages/router/src/facts.ts (what the reviewer is shown), packages/router/prompt-templates/verification.md (what the reviewer is told about it), packages/router/src/bootstrap/templates.ts and the AGENTS.md it writes (the rule about writing files), packages/router/test/ (the tests named after those files), docs/driving-a-session.md, docs/guide/ (where a session's product is described), version.json, tools/dabbler-ai-orchestration/CHANGELOG.md

Why. A member of staff reports that when a session's plan calls for a Word document, the document is much poorer than the one the same model writes outside the framework, and that it has happened more than once. The model is not the cause: the engine is started as the same program with the same model and nothing withheld. Three things the framework says and does are.

The planning instruction says that every step has a check, that a check writes nothing, and that "a generator is run as the step's work and the check proves its output is current". It was written for generated code. An author who reads it with a .docx to produce writes a script that emits the document and a check that the document matches the script. The field report of 2026-11-16 shows exactly that in a consumer repository: scripts/build-user-guide.ps1 writes docs/user-guide.docx, and two further scripts check it. Outside the framework the same model writes the document itself, opens it, reads it and puts it right. Inside, a document finished by hand no longer matches its script and fails its check, so the document is as good as a first script and no better.

The same instruction says "Over-engineering is strictly forbidden" and that value is measured by simplicity. That sentence is the operator's and is about the design of code. Read beside a document, it says not to give it styles, a contents table, tables or figures. Read beside a user interface it says the same of layout and styling, and the same member of staff spent many sessions improving the look of one. Nothing else the framework says to an author or a reviewer bears on how an interface looks, so that sentence is all an author hears about it. That those sessions went as they did because of it is an inference: they were not read for this plan.

Nobody reviews the document. The reviewer is shown a text diff: a new .docx is listed as "binary / non-UTF-8" and left out, a changed one appears as "Binary files differ", and the reviewer runs nothing. It reviews the generator script as code and never sees what the script made. Outside the framework a person looks at the first draft and asks for a better one; inside, the first draft closes the session.

The consumer repository is on another machine and was not read for this plan. The instruction's text and the reviewer's evidence were read in this repository's source; that the staff member's documents came from a generator script rests on the field report alone.
