Session 313 of 316: A stop the framework caused reaches the people who can fix it

Scope: packages/router/src/session.ts and cli/session.ts (the verb, the check and the waiver's line), packages/router/src/cli/consult.ts (the Mechanic's brief), docs/sessions/mechanic-log.md (the entry's shape), packages/router/src/driver.ts (the ways on), the Work Explorer's stop commands under tools/dabbler-ai-orchestration/src/, the tests named after each, docs/driving-a-session.md, the README, version.json and the manifests npm run stamp:version writes, tools/dabbler-ai-orchestration/CHANGELOG.md

Why. In a consumer repository the framework is an installed package. A rule that is wrong there is fixed nowhere the developer can reach, and after session 311 they will waive it and carry on -- which is right for them and teaches this repository nothing. The exception that argued for a framework change stays in one checkout's untracked record. The blocked-stop defect session 310 fixes reached here only because one developer wrote a paragraph about it by hand; the developer before them, if there was one, did not.

Round 23's two advisers both asked for the same thing: a report the person previews and sends themselves, and nothing sent for them. A state IT shop cannot have a tool posting its sessions to a public tracker, and a report nobody had to assemble is the only kind that gets filed.

The operator, 2026-11-11: a consumer's repository may hold what it should not, and a person may not read a long report carefully enough before sending it. So the report is limited to a pointer to the framework's own code, a description of the problem and a suggested fix; it carries no example unless the person writes one; and what the Mechanic drafts is read by a reviewer for anything sensitive before the person sees it. Sending two short passages to a provider that already reads the session's diffs adds no exposure, and a public issue cannot be taken back.

What. One short report: where the stop is in the framework, what is wrong and what would fix it, for a person to read and send.

Step 1 -- the report. dabbler session defect-report writes one markdown file under .dabbler/reports/ for the stop a session stands at, or with --session N the last stop that session met, and prints its path. It has four sections and no fifth. Where: the router's and the extension's versions, the engine, the vehicles, the platform, and the stop's kind, code, phase and rule name -- values the framework owns, which locate the rule in the framework's source and nothing in the repository's, and never the stop's reason, which can carry a path or a step. Problem and Suggested fix: the Mechanic's two lines for the maintainers, after step 2. Example: an empty heading that says it is the person's to write or to leave.
