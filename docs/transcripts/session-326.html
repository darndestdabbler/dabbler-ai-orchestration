Session 326 of 327: A guide page on what a session costs, and what is sent to a reviewer

Scope: docs/guide/cost-and-what-is-sent.md (new), docs/guide/README.md, tools/dabbler-ai-orchestration/README.md, version.json and the manifests npm run stamp:version writes, tools/dabbler-ai-orchestration/CHANGELOG.md

Why. Consult round 24 asked two advisers what a reader still cannot tell after reading all of the public documentation. Both ranked the same two questions highest: what a session costs, and what leaves the machine for a reviewer. The listing answers the first in one sentence ("Your costs are your provider's API spend or your Copilot seat") and nothing answers the second in one place. The operator ruled on 2026-11-12 that neither belongs in the risks table, because the honest answer has too many cases for a cell, and that it should be said elsewhere.

Step 1 -- the facts, from the source. Before a sentence is written, read and note in the step's report:

  • every place a session can call a model: the authoring engine, each review round, the unattended Mechanic, Check this stop, an adjudication, a consult; and which of them the framework starts by itself and which only a person starts;
  • whether a release session calls a model at all. The operator's understanding is that it does not, because only the framework runs. The page says so only if the source agrees;
  • what the framework can and cannot see of the cost: what a review round records, what dabbler seat-cost reads, and whether anything of the authoring engine's own spend reaches the record;
  • what a reviewer is sent, from packages/router/prompt-templates/ verification.md and verify/rounds.ts, and what it may read for itself. Checked on 2026-11-12: a reviewer reached through a Copilot seat can list, search and read files, 40 operations a round by default (verification.settings.read_budget), declared to it and measured afterwards rather than refused; a reviewer reached through an API key has no tools and sees only what it is sent, unless verification.settings.api_file_requests is on, which it is not by default; no review round can write to the repository.

Step 2 -- measured ranges, or none. From the records on this machine, take what recent sessions' review rounds cost, by reviewer model, and give a range with the models named. Where the records cannot support a number, the page says what the cost depends on and gives no number. No figure on the page is an estimate.

Step 3 -- the page. docs/guide/cost-and-what-is-sent.md, in the guide's own shape (a claim, the mechanism, where to see it), one sitting long. It says:

  • What a session costs, as three cases in the operator's terms. A subscription on both sides (the authoring tool's own plan, and a GitHub Copilot subscription for the review): the cost is contained while the work stays inside the plans' monthly limits. Copilot billed by use, or API keys for either side: the cost follows the models chosen. With a top-tier frontier model on both sides, expect dozens of dollars a session, and now and then a session past a hundred. A release session: whatever step 1 found.
  • Prices move, so watch them. Models differ in price many times over, and the prices change as new models arrive. The page says plainly that a person should keep an eye on what sessions cost, and names where to look.
  • Where the prices are, as links to each company's own pricing page, the operator's list: Google (https://aistudio.google.com/docs/pricing), OpenAI (https://openai.com/api/), Anthropic (https://platform.claude.com/docs/en/about-claude/pricing) and GitHub Copilot (https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing). Each link is opened before it is written, and one that no longer leads to prices is replaced by the page that does.
  • The operator's own experience, given as one person's experience on the date of writing and not as a price list: the top Anthropic models (Opus, Fable) cost much less through a Claude Max subscription than through GitHub Copilot billed by use; and Sonnet writing the code with Terra or Argon reviewing it is capable enough for most work at a reasonable price, with a session often under $10. Each model is named as the Configuration lists it.
  • What moves the cost, each with the setting that changes it: the model chosen for each role in the Configuration, the round cap (verification.settings.max_rounds), and the Mechanic's delegation.
  • What is sent to a reviewer: the session's section of the plan, the diff, the decisions, the list of changed files with no test named after them, and a prompt that tells the reviewer to assume the work is flawed and try to prove it; and what it may read beyond that, by vehicle, as step 1 found.
  • Which companies receive code: the author's provider and the reviewer's, always two; a third only when a person asks for an adjudication.
  • Where to see it: dabbler seat-cost, the round's own record, and dabbler configuration explain.

Step 4 -- the links. docs/guide/README.md gains the page's line. On the Marketplace page, the sentence under *Get started* that names the costs links to the page and says no more than it does now.

Step 5 -- the number. version.json goes to 3.32.5, stamped with npm run stamp:version -- a patch: wording only. The changelog's 3.32.5 section covers this session and 325: the risks table now names watching and auditing, the round cap and the Mechanic's default, and the guide has a page on cost and on what a reviewer is sent.
