ISSUES FOUND

- **Issue 1:** The new tests-authoring flow only works on `copilot-cli`; on the supported `api` and `offline` transports every `test-write` block is refused.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/transports/copilot.py:25-33, ai_router/router-config.yaml:54-60, ai_router/agency.py:13-18, ai_router/agency.py:269-320, ai_router/agency.py:726-730, ai_router/testphase.py:191-227, ai_router/workflow.py:221-228, ai_router/workflow.py:821-848`
  - **Failure scenario:** A no-seat deployment sets `transport.profile: api` as the shipped config says to do via local override, or a scripted run uses `offline`. The verifier can answer with a valid `test-write` block, but `grant_for_transport()` returns `MODE_NONE`, so `briefing()` omits the block format and `_confine()` refuses every write for lacking `OP_WRITE`. `workflow author-tests` therefore produces no accepted test files, and `workflow test` then refuses because no test has been authored. This is probable rather than merely possible because `api` and `offline` are documented, supported operating modes, not stray edge cases.
  - **Acceptance criterion:** `JUDGMENT - On api and offline transports, a valid tests-phase response containing a test-write block must produce accepted writes from workflow author-tests instead of the blanket "no write operation" refusal path.`
  - **Details:** **Violation** — the code says the verifier's one write is framework-performed "on either transport," and the transport docs say the API path remains fully supported; session 11's deliverable is specifically the tests phase with that write grant turned on. **Impact** — a substantial supported deployment class cannot create or modify verifier-authored tests at all, so the core session-11 feature is unavailable and a reasonable reviewer should block. **Evidence** — non-Copilot transports are collapsed to `AgencyGrant(MODE_NONE, (), 0)`, `briefing()` returns `""` whenever `mode != MODE_TOOLS`, and `_confine()` rejects every proposal when `OP_WRITE` is absent; `testphase.author()` uses that grant both to brief the model and to apply its response, and `workflow.py` only reports "nothing was written" / later "no test has been authored." The correct answer is to decouple the framework's `test-write` grant and its prompt briefing from read-tool availability so API/offline authoring can still emit and apply test files.
