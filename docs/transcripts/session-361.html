Session 361 of 365: The Work Explorer offers only what its verbs take, and a stop's bar goes with the stop

Scope: packages/router/src/views/workExplorer.ts (which actions a session's row offers), packages/router/src/progress.ts with the progress projection's schema and its generated type (whether a standing stop can be waived), tools/dabbler-visual-studio/Dabbler.VisualStudio/NoticeWatcher.cs (the editor's bar for a session that needs a person), and the tests named after each

Why. Session 360's walk in Visual Studio found three things a developer meets at a stop, and none was small enough to fix inside the walk.

Step 1 -- Review exception only where a waiver can go. A session's row offers Review exception on every standing stop, because the row knows who the stop waits on and not what kind it is. On a blocked stop, which the walk produced, it runs session waive and the router refuses: *"a 'blocked' stop has nothing to go past"*. The projection says whether the standing stop is one session waive accepts, read from the one list it reads (WAIVABLE_STOP_KINDS), and the row offers Review exception only then. The VS Code extension and the Visual Studio extension both take the row's actions as the router gives them, so neither changes.

Step 2 -- a way back to the engine on the session's own row. With the engine's terminal closed mid-session, the session's row offered nothing that reopens it; the repository's row did, because its Start Session re-registers the session in flight, which is how a session continues. The session in flight's row offers that same start as Continue Session where no stop stands -- the action and its label exist already, for a wait on funds. It adds no way to start an engine the repository row does not already offer.

Step 3 -- the bar goes when the stop does. Visual Studio says *"session N is paused"* in an information bar across the editor, and the bar stayed after the walk rolled the session back, until closed by hand. It closes itself when the next notice for that repository says the session has moved on.

Non-goals. Knowing whether an engine is still running. Any new stop kind or any change to what session waive accepts. The Configuration window.

Tests. In workExplorer.test.ts: a blocked stop's row offers no Review exception and a tests stop's row does; a session in flight with no stop offers Continue Session. In progress.test.ts: the projection says a blocked stop cannot be waived. In the Visual Studio library, the test named after the file that decides when the bar closes.

Releasable. No: it ships in 3.37.0, in session 363.
