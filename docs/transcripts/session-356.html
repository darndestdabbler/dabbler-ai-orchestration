Session 356 of 362: The catalog, a key, and Start Session with Different Models, from Visual Studio

Scope: tools/dabbler-visual-studio/ (the three actions)

Why. These complete what a developer on a new machine needs before a first session: a catalog read, a key stored, and a session started with models other than the configured ones.

Step 1 -- Update the Catalog. After its confirmation, dabbler discovery refresh runs and its lines are shown in the Dabbler Session pane. Where the catalog has never been read, it runs once without being asked, as in VS Code.

Step 2 -- Store a Key. dabbler auth set asks for the key itself, so it opens in a tab of the Dabbler window of Windows Terminal. The key is never typed into Visual Studio and never passes through the extension.

Step 3 -- Start Session with Different Models. The engine, the model, the reviewing vehicle and the two reviewers are asked in turn from the choices the router gives, and the start runs with them.

Non-goals. Any store of keys in Visual Studio.

Tests. In the library: the start built from five answers carries each as its flag; one left at its default carries none.

Releasable. No.
