**A. Rungs to drop:** Drop the special “counter → author agreement → special test → special revert” workflow. A reviewer’s concrete alternative can simply be an ordinary finding: the author accepts and fixes it, or disputes it, using the existing verification machinery. Keep one reviewer pass before escalation, but make its result “endorse” or “return one concrete finding”; if that does not resolve the problem through normal work, show the existing human modal. Reuse the existing checks and Git rollback rather than adding proposal-specific states.

**B. Two AIs passing an outcome change:** No—not for changing the promised outcome, closing as held, bypassing a gate, publishing differently, or weakening required checks. “No rule stands above finishing” supports escalation and an explicit human exception; it does not make two correlated model judgments equivalent to owner consent. In unattended mode, such a session should pause while other sessions continue. Human-after-the-fact reporting is acceptable only when the reviewer’s alternative preserves the promised outcome and passes the existing checks—in that case it is ordinary implementation, not an exception.

**C. Ride on the round?:** Yes. Represent the proposal as a specially labelled finding in the existing verification round. An endorsement records reviewer support but does not itself authorize an outcome-changing exception; a counter is simply a concrete finding for normal author disposition. This is less code than a separate proposal negotiation path, although the existing human modal remains the final disposition for genuine exceptions.

**D. Score:** Count-and-show only. Scoring rejected asks or inferred “workarounds” will still encourage concealment and creates a classification system that is easy to game; visible per-session counts provide accountability without making honest escalation costly.

**E. Simplest first version:** When the author raises a last-resort proposal, ask the Primary Reviewer once to endorse it or return one concrete alternative. If the alternative preserves the outcome, process it as an ordinary finding and run the normal checks; otherwise—or if it fails, is disputed, or the reviewer endorses an actual exception—send the existing modal to the human with the proposal, reviewer response, and relevant test output.

**One recommendation:** Ship reviewer triage, not AI authorization. Reuse the existing finding/disposition/check/rollback path for workable alternatives, and preserve human approval for every genuine change to the promised outcome or gate. This removes bad or unnecessary requests before they reach a person without adding a parallel workflow or quietly weakening the trust boundary already agreed.
