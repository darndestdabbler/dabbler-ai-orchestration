Why. The Configuration section shows who authors, who reviews, the vehicle each is reached through, each model, the Mechanic and the keys, with the layer that decided each value. Step 1 -- the move. The Configuration half of solutionTreeModel.ts, its types, labels and row descriptions, moves to packages/router/src/views/configuration.ts, with the Mechanic's two rows, which the extension reads by a separate road today. The repositories and modules half stays where it is.

Step 3 -- what may be chosen. A row that can be set carries its choices: each one's label, its detail, whether this machine can reach it and why not, and the dabbler configure command that sets it, for this repository and as the machine's default. dabbler configuration options --json prints the same lists for a person or a script. A model that is typed and not picked says so.

Step 4 -- the extension reads it. The Solution Explorer joins the router's rows under its Configuration node, and each picker lists the choices its row carries and runs the command the chosen one names. Nothing a person sees changes.

Non-goals. Any change to a row, a choice, a layer or what configure writes. The repositories and modules of the Solution Explorer. Update the Catalog and Store a Key, which run in a terminal and stay as they are.

Tests. The Configuration tests in solutionTreeModel.test.ts move to configurationView.test.ts, rewritten for node --test; none is dropped. One new test: every choice on a row names a command the configure parser accepts.

Releasable. Yes, as 3.36.0 in session 348.
