ISSUES FOUND

The `configfile: pytest.ini` widening bug is fixed; the import-expansion part of the old read-surface nit is resolved, but the read surface itself still overshoots §3.d and the new location matcher regresses common traceback formats.

- **Issue 1:** `_LOCATED` drops common traceback frames, so the real failing implementation file can fall out of the envelope
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/fixloop.py:76-81, ai_router/fixloop.py:241-271, docs/session-sets/148-the-session-framework/project-work-plan.md:237-247`
  - **Failure scenario:** A normal Python failure still produces a path-based failing-test line such as `FAILED tests/test_add.py::test_adds`, but the only implementation frame is the standard traceback form `File "app.py", line 4, in add`. That traceback shape is common in Python code and subprocess failures. `failures()` still identifies the test, but `_LOCATED` ignores the source frame, so `build_envelope()` omits `app.py` and a `fix-write path=app.py` is refused as outside the envelope.
  - **Acceptance criterion:** `JUDGMENT - A suite output containing a failing declared test plus a traceback frame like 'File "app.py", line 4, in add' causes build_envelope(...).implicated to include app.py when app.py exists inside the repo.`
  - **Details:** **Violation** — `project-work-plan.md` says “A fix round is handed only the failing test names, their output, and the files the failures implicate.” **Impact** — on a common traceback format, the fix round cannot write the actual broken source file, so the bounded fix loop fails on an ordinary Python failure shape and a reasonable reviewer should not merge it. **Evidence** — the new `_LOCATED` regex only matches paths immediately followed by `:digit` or `::`, and `implicated_paths()` now admits only failing-test files plus those `_LOCATED` matches. A `File "app.py", line 4` frame satisfies neither condition, so `app.py` is not implicated. The correct answer is to keep excluding bare mentions like `configfile: pytest.ini` while also recognizing common positioned traceback forms such as `File "...", line N`.

- **Issue 2:** The fix round's Copilot read scope is still wider than §3.d: it includes the whole session diff, not just implicated files
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/fixloop.py:117-118, ai_router/fixloop.py:455-466, ai_router/agency.py:340-358, ai_router/agency.py:479-542, docs/session-sets/148-the-session-framework/project-work-plan.md:242-247`
  - **Failure scenario:** On the Copilot CLI path, any ordinary session that has touched an unrelated second file before the full-suite run makes that file readable and counted in-scope, because `build_envelope()` carries the full session diff and `fix()` hands `envelope.paths` to the read grant. That is probable in real sessions, which routinely have code, tests, and session-doc updates in flight together. The generator is therefore explicitly invited to inspect unrelated session files, and the round record will still attest that those reads stayed within scope.
  - **Acceptance criterion:** `JUDGMENT - On the Copilot CLI path, fix() grants glob/grep/view only for the implicated-file set (including the failing tests' own files), while write_envelope may still remain the full envelope of session_paths plus implicated files.`
  - **Details:** **Violation** — the same plan text says the fix round receives “only the failing test names, their output, and the files the failures implicate.” **Impact** — the seat path's read boundary is the declared scope plus the in-scope/out-of-scope log; by making all session-diff files part of that scope, the implementation still blesses unrelated reads in the one round this session exists to constrain, which is merge-blocking. **Evidence** — `Envelope.paths` unions `session_paths` and `implicated`, `fix()` now uses that whole union as `scope`, `agency.briefing()` exposes `grant.scope` as the `glob`/`grep`/`view` surface, and `AgencyRecord` uses the same scope to mark reads as in- or out-of-scope. The correct answer is to leave the write envelope alone but build the Copilot read grant from the implicated set only.
