ISSUES FOUND

- **Issue 1:** `build_envelope()` treats any in-repo path token in suite output as "implicated", so `workflow fix` can rewrite unrelated files such as `pytest.ini`.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/workflow.py:1121-1129`, `ai_router/fixloop.py:233-279`, `ai_router/agency.py:823-829`, `ai_router/router-config.yaml:416-425`, `pytest.ini:1-8`
  - **Failure scenario:** On this repo's default `python -m pytest` full-suite run, pytest's standard header names the active config file (`configfile: pytest.ini`). `implicated_paths()` scans every path-like token in the entire run output, so `build_envelope()` adds `pytest.ini` to `Envelope.paths` even when no failure touches it. `workflow fix` then passes that envelope to `_confine()`, which will accept a `fix-write path=pytest.ini` block. That is probable on ordinary red suite runs here because the declared suite is pytest and the repo has a `pytest.ini`; it lets a fix round alter runner configuration instead of staying confined to the session diff plus files implicated by the failures.
  - **Acceptance criterion:** `JUDGMENT - When a red suite run mentions an in-repo file outside any failing test line or traceback (for example pytest's "configfile: pytest.ini" header), that file is not added to the fix envelope and a fix-write to it is refused unless it is actually implicated by the named failures.`
  - **Details:** **Violation** — the task requires that "The fix round receives **only** failing test names, their output, and the files implicated by the failures" and that "Writes are restricted to the session diff plus implicated files ... **A write outside the envelope is rejected, not discouraged.**" **Impact** — the enforced boundary is wider than promised on the main path: a red pytest run can make unrelated repo files writable, including `pytest.ini`, which is enough to weaken or reroute the suite rather than fix the code. That changes the merge decision because the envelope is the feature of this session. **Evidence** — `_run_fix()` builds its envelope straight from the stored suite output (`ai_router/workflow.py:1121-1129`); `implicated_paths()` in `ai_router/fixloop.py` keeps any in-repo file token found anywhere in that output (`233-249`); `build_envelope()` unions that set into the write envelope and never uses its `selection` parameter to narrow it to the named failures (`252-279`); `_confine()` in `ai_router/agency.py` then accepts any path present in `grant.write_envelope` (`823-829`). With this repo's `python -m pytest` suite (`ai_router/router-config.yaml:416-425`) and live `pytest.ini` (`pytest.ini:1-8`), the correct behavior is to derive implicated files from the named failing tests and their failure frames, not from arbitrary path-shaped tokens anywhere in runner output.
