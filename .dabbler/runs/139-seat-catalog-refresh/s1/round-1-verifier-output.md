ISSUES FOUND

**Issue 1:** Unknown keys inside `transports.copilot-cli` overrides are accepted instead of refused.
- **Category:** Correctness
- **Severity:** Major
- **Evidence paths:** `ai_router/config.py:110-141`, `ai_router/config.py:224-238`, `ai_router/schemas/router-config.schema.json:126-132`, `ai_router/router-config.yaml:66-79`
- **Failure scenario:** A Copilot-seat operator hand-authors `local-overrides.yaml` to adjust the exact block this session needs for `copilot-cli` dispatch and mistypes a key such as `lockfil` or `timeotus`. Because `transports` is an open schema object and the custom validator stops recursing there, load succeeds and the bundled `lockfile`/`timeouts` remain in effect. This is probable for a partial, manually maintained override file whose purpose is to prevent silently ignored machine-local settings.
- **Acceptance criterion:** `JUDGMENT - Loading bundled config with a project local-overrides.yaml containing an unknown key under transports.copilot-cli, e.g. timeotus, must fail loudly naming that key, while valid transports.copilot-cli keys still load.`
- **Details:** **Violation:** The spec requires “A key the schema does not know is refused at load, not ignored” and says “A silently-dropped override is the failure this file exists to prevent.” **Impact:** A reasonable merge decision changes because the new local override tier still silently drops typos in the most important Copilot transport override block, causing sessions to run with stale bundled seat settings rather than the operator’s intended local configuration. **Evidence:** `_reject_unknown_overlay_keys()` explicitly `continue`s when a schema has no `properties` (`ai_router/config.py:136-141`); the schema declares `transports` only as `{ "type": "object" }` (`ai_router/schemas/router-config.schema.json:132`); and `_validate_copilot_block()` only checks required keys plus `timeouts` when present, not unknown sibling keys (`ai_router/config.py:224-238`).
