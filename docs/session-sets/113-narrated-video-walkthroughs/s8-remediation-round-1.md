Round 1 (the discovery pass) raised **one** blocking finding:

> **F1, Major, Correctness** — the scripted VS Code recorder treats a gdigrab
> guard-aborted partial file as a normal completed video artifact.

It was **accepted, not disputed**, and fixed.

**Remediation was performed once, after BOTH discovery passes**, which is what
the loop prescribes: the supplementary pass ran before any code changed, so
round 2's two findings were merged with this one and all three were fixed in
a single pass. The full write-up of what was found, why each finding was
real, and what changed — including the run in this session's own measurement
that had already produced an instance of F1 — is in
[`s8-remediation-round-2.md`](s8-remediation-round-2.md).

In brief, for F1: a guard abort is now a first-class outcome of the recording
path. The partial file is kept as evidence under
`recording-partial-aborted.mp4`, **no `os-video` artifact is registered**, so
the manifest no longer claims a video for the run, and the abort reason is
carried on the result and in the run's notes.

`s8-gdigrab-capture-measurement.json` was regenerated by a full re-run rather
than patched.
