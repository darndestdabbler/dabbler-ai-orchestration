**ISSUES FOUND** — the transition validator still allows a new target to skip the sequence on its very first `entered` event, which breaks the core gate this session was meant to add.

- **Issue 1:** First `entered` event can jump directly to any step.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `ai_router/workflow.py:102-106`, `ai_router/workflow.py:161-165`, `docs/session-framework-plan.md:66-79`, `docs/session-framework-spec.md:103-105`
  - **Failure scenario:** On a clean workspace, an author/orchestrator can run the public workflow entrypoint to enter `build` as the first event for a target. Because `append()` passes `None` for targets with no history and `validate_transition()` returns immediately when `state is None`, the skipped prior steps are persisted instead of refused. This is probable because every target begins with no folded state, so the unchecked branch is the normal first-entry path.
  - **Acceptance criterion:** `python -m ai_router.workflow enter build --component csv-model --workspace-root examples/csv-walkthrough`
  - **Acceptance expectation:** exit 1
  - **Details:** Violation: the task requires “forward entry is sequential,” and the spec says “A step cannot be skipped.” Impact: this reopens the exact gate hole A2 was meant to close; a target can be recorded at the final step without plan/decompose/contracts/mocks/integration history, changing the merge decision because record authority is not actually enforced. Evidence: `validate_transition()` validates the target step, then returns before any sequence check for `state is None`; `append()` invokes it with `fold(read(root)).get(target)`, which is `None` for a new target. The correct behavior is to constrain the first entry to the declared/default starting step, not to allow any step as an origin.
