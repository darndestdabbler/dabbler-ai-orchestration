**ISSUES FOUND**

- **Issue 1:** The Explorer can derive active/start-time fields from an inferred state when `session-state.json` is absent.
  - **Category:** Correctness
  - **Severity:** Major
  - **Evidence paths:** `docs/session-sets/127-the-active-step-shows-in-progress/spec.md:63`, `ai_router/session_checklist.py:331`, `ai_router/session_state.py:1773`, `tools/dabbler-ai-orchestration/src/utils/sessionState.ts:241`, `tools/dabbler-ai-orchestration/src/utils/fileSystem.ts:1190`, `tools/dabbler-ai-orchestration/src/utils/fileSystem.ts:1315`, `tools/dabbler-ai-orchestration/src/utils/fileSystem.ts:1578`, `tools/dabbler-ai-orchestration/src/providers/sessionStepModel.ts:248`
  - **Failure scenario:** A legacy or consumer session set has `spec.md` plus a nonempty `activity-log.json` but no `session-state.json`, which the extension already treats as a supported fallback path. The Explorer infers an in-progress state, passes that inferred object into `sessionFlightFacts`, and can mark a step active / assign start times. Python’s `session_checklist.build_rows` reads the actual missing state file and derives no active step or start time, so the two surfaces disagree on a real supported path.
  - **Acceptance criterion:** `JUDGMENT - For a session set with spec.md + nonempty activity-log.json and no session-state.json, readSessionSets may still use in-memory inference for set/session bucketing, but the step ledger flight facts must be NOT_IN_FLIGHT ({ inFlight: false, startedAt: null }) and the Explorer rows must match Python build_rows with isActive=false and startedAt=null.`
  - **Details:** Violation: the spec says the active step is derived only “in a session `session-state.json` says is in flight,” and the corpus readme says “ABSENT means no state file … no derivation at all.” Impact: this is exactly the contract the session calls worse than silence: the tree can show a current step/start time that the Python checklist does not, changing the merge decision because Session 2’s core deliverable is row-for-row parity. Evidence: Python `read_session_state` returns `None` when the file is absent, while the extension’s `inferStateInMemory` creates an in-progress state from `activity-log.json`; `readSessionSets` then stores that as `normalizedState` and passes it to `buildStepLedger`, which calls `sessionFlightFacts` and arms the derivation.
