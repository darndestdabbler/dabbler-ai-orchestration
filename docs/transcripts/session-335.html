Why. The same investigation, and confirmed in this tree: what the author is asked to plan from and what the reviewer holds the session to can be different text, and neither is told.

  • extractSpecExcerpt returns the whole plan when no heading matches the session. planAsk expects nothing in that case and has words for it that are never reached; the reviewer is handed every session in the file as "the session's plan, verbatim".
  • Three functions find a session's section, each by its own rule. extractSpecExcerpt and approvedContractChange run to the next session heading, so a heading that is not a session's is swept into the section before it: in this plan, the part headings between sessions; in the staff repository, a "Proposed follow-up" the session itself appended. readPlanSection, for the transcript, stops at any ###.
  • The reviewer reads the section from the working tree. A session that edits the plan, as session 140 of the staff repository was asked to, is reviewed against the text it wrote. The contract control already reads the plan as committed at the session's start, for this reason.

Step 1 -- one reader. One function takes the plan's text and a session's number and returns that session's section, or nothing. A section ends at the next heading of level three or above, and a line inside a fenced block is not a heading: this plan has one such line today. The plan ask, the reviewer's prompt, the contract control and the transcript all call it, and the private copies are deleted. For the contract control this is a change, in the direction of refusing: a **Contract change.** paragraph under a level-three heading of its own, below the session's, is no longer in the section, where the transcript already left it out. The changelog says so.

Step 2 -- no section is said, never the whole file. The plan ask says what it already has the words for. The reviewer's prompt says the plan has no section for this session.

Step 3 -- author and reviewer are given the section as it stood at the start. The plan ask and specExcerpt both read the plan at the session's start commit. Where the section in the tree differs from it, the reviewer's prompt carries both, and says which is which: the text at the start is what the session is held to, and the other is what the section reads now. It says that a difference relaxes nothing by being there: where the later text removes or weakens something the start text asked for, the reviewer reports that as a finding, and a person decides it by the ways a finding already has. It says too that nothing shown grants a contract change, which is the control's alone to read.
