ISSUES FOUND

- **Issue 1:** `decision_journal` accepts self-inconsistent records for human-owned rubric lines.
  - **Category:** Correctness
  - **Severity:** Major
  - **Failure scenario:** A normal orchestrator/CLI caller hand-builds a decision record for a verification waiver or split consensus stop and supplies the separately-required `authority`, `rubric_line`, and `verification_effect` fields inconsistently. The blessed writer currently accepts `rubric_line="verification-reduction"` with `verification_effect="none"` and no `operator_attestation`, and accepts `rubric_line="escalate-to-human"` with `authority="ai"`. Those are probable mistakes because the new API requires manually assembling multiple overlapping semantic fields, and they hit the two human-stop paths this session explicitly added.
  - **Acceptance criterion:** `JUDGMENT - validate_record()/record_decision() must reject records where rubric_line="verification-reduction" unless verification_effect="reduces" and human authority has a non-empty operator_attestation, and must reject authority="ai" with rubric_line="escalate-to-human".`
  - **Details:** **Violation:** the task says the operator record for a verification reduction “requires a non-empty `operator_attestation`,” and the workflow says tiebreak 6 is “Consensus splits → the human, as an education-mode brief.” **Impact:** the audit ledger can record a carve-out without the required operator attestation, or mark a human escalation as `[A]`, defeating the structural decision-rights guarantee a reasonable reviewer would require before merge. **Evidence:** `validate_record()` only requires attestation inside `if record.verification_effect == "reduces"` (`ai_router/decision_journal.py:406-420`) and only blocks `_HUMAN_TRIGGERS_SET` under AI authority (`ai_router/decision_journal.py:392-404`), while `escalate-to-human` is in `AI_TIEBREAKS` (`ai_router/decision_journal.py:88-103`). Direct probes confirmed both malformed records are written successfully.

#### NITS

- **Nit:** `make_record()` coerces option reversibility with `bool(item["reversible"])`, so a JSON value like `"false"` is stored as `true` (`ai_router/decision_journal.py:505-511`). That can corrupt audit metadata for malformed hand-authored payloads, but typical JSON callers will use real booleans.
